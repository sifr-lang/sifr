## Non‑blocking observations
1. **Orphan `bare_stdlib_import_canonical/baselines/`** — the fixture is referenced in the contract harness (`crates/sifr_driver/src/bin/diagnostic_contract_harness.rs:38`) but **not** in `verification/suites/manifest.json`, while other `_canonical` harness fixtures (`workspace_missing_import_canonical`, `workspace_ambiguous_import_canonical`, `workspace_namespace_collision_canonical`) don’t carry a `baselines/` directory. Either add it to the manifest or delete `crates/sifr/tests/verification/project/bare_stdlib_import_canonical/baselines/` so it doesn’t silently drift.
2. **`ResolutionError::to_source_diagnostic` duplicates the bare‑stdlib check unconditionally** (`crates/sifr_driver/src/project/discovery.rs:273`) but `parse_import_closure_source_modules` already filters by `dependency.is_absolute_import` before calling it (`:733`). For absolute imports the inner check is dead code; for relative imports it can mis‑reclassify a name like `from .math import x` as a bare‑stdlib import with empty `imported_names`. Either drop the inner check or thread `is_absolute_import`/`imported_names` into the method.
3. **Inconsistent primary span for SIFR‑IMPORT‑0008** — lowering `Stmt::ImportFrom` uses `import_from.range()` (the whole `from ... import ...`), while lowering `Stmt::Import` and both discovery emitters use the module name range. Fixture `bare_stdlib_from_collections.sifr` expects `col=1`, fixtures and discovery baselines highlight just the module name. Normalizing the lowering `ImportFrom` to `module.range()` would give consistent UX across layers (and matches the verification baselines).
4. **`hir_diagnostic_to_rendered` flattens `message_template` to `"{message}"`** (`crates/sifr_frontend/src/query_diagnostics.rs:143`). Discovery emits the registry template verbatim; single‑file lowering does not. The structured args are still in the JSON envelope, but JSON consumers see different `message_template` strings between the two modes. Pre‑existing limitation of how coded HIR diagnostics are rendered; not unique to M1.
5. **`bare_stdlib_help` is duplicated** in `crates/sifr_lowering/src/lower/import_diagnostics.rs:76` and `crates/sifr_driver/src/project/discovery.rs:520`. Acceptable for crate boundaries but a candidate to lift into `sifr_stdlib` alongside `BareStdlibMatch`.
6. **Workspace fixture path artifact** — `workspace_bare_stdlib_import/baselines/check-human.stderr.txt:8` shows `<WORKSPACE>/..././math.sifr` from `source_roots = ["lib", "."]`. Pre‑existing tried_paths quirk; cosmetic.
