Non-blocking notes (worth a follow-up, do not block this PR)
1. `lib/sifr/process.sifr:369-387` — the async path (`async_run`/`async_output`) does not consume the new `command.stdin_mode`. A user who sets `Command.stdin(Stdio("pipe"))` and then calls `async_run` will silently get default stdin. `spawn` loudly rejects `stdin_bytes`, but async silently ignores `stdin_mode != "inherit"`. Consider extending the same typed-rejection pattern (e.g. raise `ProcessError("async process stdin mode requires owned pipe support")` when `stdin_mode != "inherit"`) so the asymmetry doesn't bite users between waves. Acceptable as-is because this wave is sync-only and the traceability already lists "async stdin/owned pipes" as later M4 work.
2. `lib/sifr/process.sifr:96-100` — when `process_pipe_write_all` fails, the native writer is dropped from the table but the Sifr-level `self._closed` flag stays `False`. A subsequent `close()` will then call into the native helper and surface `"process pipe writer handle is closed or unknown: {handle}"` rather than the friendlier `"process pipe writer is already closed"`. Both are typed `ProcessError`s, so no correctness issue, but flipping `_closed = True` in the `write_all` failure path would yield a cleaner post-mortem story.
