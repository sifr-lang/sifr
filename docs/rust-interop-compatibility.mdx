Rust interop compatibility is evidence-based. A surface is listed as supported
only when the Rust interop verification area has passing positive and negative
fixture evidence for that exact contract.

## Categories

| Category | Meaning |
| --- | --- |
| `supported` | The contract has passing positive and negative fixture evidence for the stated execution kind. |
| `supported-through-bridge` | The contract is supported through an explicit local or shared Rust bridge; direct binding is not implied. |
| `unsupported-by-design` | The surface is rejected intentionally with passing diagnostics and no fallback path. |
| `future-owned-by-separate-phase` | The surface is documented but not listed as verified support because at least one evidence direction is not passing. |

## Supported

| Surface | Evidence |
| --- | --- |
| Direct compatible functions, including `crc32fast`, `blake3`, `sha2`, `uuid`, and compatible `regex` shapes | Passing cargo-probe positive and negative fixtures. |
| Structured dotted Rust paths | Passing diagnostics for valid paths and rejection of string or legacy syntax. |
| Same-workspace crates as explicit Cargo dependencies | Passing contract evidence for declared path dependencies and undeclared-root rejection. |
| Opaque handle contracts and handle state transitions | Passing Send/Sync/Copy/close probes plus runtime closed/poisoned state evidence. |
| Panic policy contracts and abort-profile trust | Passing contract evidence for declared panic surfaces and recoverable abort rejection. |
| Async signature probing, blocking I/O classification, and CPU-heavy classification | Passing positive and negative diagnostics for the supported contract surface. |
| Thread-safe callback policy declarations | Passing contract evidence for bounded policy and missing backpressure rejection. |
| Zero-copy bytes and core view contracts | Passing contract evidence for owner/lifetime views and copy-fallback rejection. |

## Supported Through Bridges

| Surface | Evidence |
| --- | --- |
| Package-local bridges such as `bridge.*` adapters over `blake3` | Passing package projection and bridge-root diagnostics. |
| Shared bridge crate boundaries | Passing evidence for stable runtime types and rejection of package-specific generated bridge imports. |
| Arrow record batch metadata | Passing contract-only evidence through explicit shared bridge declarations. |
| Tensor and DLPack handoff metadata | Passing contract-only evidence for explicit ownership and rejected implicit transfer. |
| Advanced data and tensor ecosystem metadata | Passing contract-only evidence for shared bridge metadata over `datafusion`, `polars`, `ndarray`, and CPU-only `candle`. |

## Unsupported By Design

| Surface | Evidence |
| --- | --- |
| Unsupported direct Rust signature shapes, including arbitrary lifetimes, raw pointers, trait objects, closures, unconstrained generics, and unsupported containers | Passing diagnostics; Sifr requires an explicit bridge adapter instead of implicit conversion. |
| Rejected Rust dynamic ABI loading, `dlopen`, `extern rust`, `from rust import`, string targets, legacy `crate=`/`path=`, hidden Tokio runtimes, generated `block_on`, and silent zero-copy copy fallback | Rejected by the architecture and stale-draft checks; no compatibility shim is provided. |

## Future-Owned

These rows are documented so package authors do not infer support from the
architecture text alone. They are not listed as verified support until their
fixture evidence becomes passing in both directions. They are tracked by
`plans/issues/active/rust-interop-runtime-ecosystem-certification.md` and must
not be advertised as stable Rust interop support while they remain future-owned.

| Surface | Current evidence state |
| --- | --- |
| Full bridge type value roundtrips for `serde`, `serde_json`, `thiserror`, `bytes`, and `indexmap` | Unsupported containers pass; positive value roundtrip evidence is planned. |
| Resource-shaped opaque handles for `reqwest`, `rusqlite`, `tokio-postgres`, and `redis` | Runtime close/aclose and aliasing evidence is planned. |
| Generated panic wrapper emission and mapper-panic fallback behavior | Runtime generated-wrapper evidence is planned. |
| Loopback `reqwest` async runtime behavior | Runtime loopback and hidden `block_on` evidence is planned. |
| Call-scoped callbacks and subscription callbacks over `tokio-tungstenite`, Redis pub/sub, and `notify` | Runtime callback lifetime, cancellation, and shutdown evidence is planned. |
| Backend/service package certification for `axum`, `tower-http`, and `sqlx` | Compile/probe and `.sqlx/` offline-artifact evidence is planned. |
| CLI/tooling package certification for `clap`, `tracing`, `tracing-subscriber`, and `anyhow` | Compile/probe and unsupported `anyhow` surface evidence is planned. |
| Native-link/build-script certification for `cc`, `bindgen`, `cxx`, and `zstd` | Trusted and untrusted native-link evidence is planned. |
| Proc-macro/build-script certification for `serde_derive` and `prost-build` | Trusted proc-macro and pre-execution rejection evidence is planned. |
| Locked, offline, and frozen Cargo certification | Cache-hit and lockfile-drift evidence is planned. |

The machine-readable source of truth is
`verification/areas/rust_interop/data/rust_interop_compatibility_matrix.json`.
