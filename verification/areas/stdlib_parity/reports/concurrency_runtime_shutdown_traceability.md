# Concurrency Runtime concurrency/runtime readiness Shutdown Traceability

Capability: `concurrency-runtime shutdown/diagnostics`

Status: Closed; signal value-model foundation covers portable `sifr.signal.Signal`, `sigint()`, `sigterm()`, `SIGINT`, `SIGTERM`, and `strsignal(signal)` evidence, structured signal stream shape/lowering covers Ctrl-C and Unix SIGTERM shutdown waits, deterministic Unix signal-delivery evidence covers child-sent Ctrl-C, SIGTERM, and shutdown-stream waits, deterministic cleanup evidence includes timeout-cancellation `finally` cleanup plus no-value and value-carrying generic `sifr.resource.nullcontext(...)`, cleanup stacks and owned closing helpers are closed as unsupported diagnostics, task context value types are importable through `sifr.task.Context` / `ContextKey[T]`, explicit `TaskGroup(ctx=Context(...))` and `task.spawn_scoped(..., ctx=Context(...))` propagation is observable through `sifr.task.current_context()`, and structured runtime diagnostic events lower to `tracing` plus fixed-schema `metrics` counters behind Sifr-owned diagnostic types. Non-Unix signal delivery remains intentionally host-limited future evidence, not an readiness blocker, until a deterministic non-Unix runner can deliver real host console-control events.

## Capability Boundaries

- `sigint()`, `sigterm()`, `SIGINT`, `SIGTERM`, and `strsignal(signal)` are value-model evidence only; awaitable `ctrl_c()`, `terminate()`, and `shutdown_stream().next()` now have Unix delivery evidence through delayed child-sent signals, while non-Unix delivery remains host-limited.
- Unsupported signal APIs are intentionally absent from `sifr.signal` so static imports produce stable diagnostics instead of runtime surprises.
- `pthread_sigmask` is grouped with unsupported signal APIs in the current fixture set because no safe mask-mutation surface exists; it remains host-limited for any future explicitly designed Unix-only API.
- `cancellation_cleanup_runs` covers language-level cleanup ordering under timeout cancellation, and `nullcontext()` / `nullcontext(value)` cover the supported no-op resource helper. Cleanup stacks and owned closing helpers are closed as unsupported diagnostics in this capability until an owned-close protocol can preserve cleanup errors honestly.
- Additional non-Unix signal delivery harnesses remain future host-limited evidence before stream delivery can be marked fully portable. A local fake or skipped fixture is not sufficient; future support must run on a non-Unix host and deliver a real host console-control event.
- `Context`, `ContextKey[T]`, `empty_context()`, and `current_context()` are Sifr-owned context surfaces. Explicit propagation is label-based and immutable at the task boundary; Python `contextvars` dynamic mutation and implicit ambient request mutation remain out of scope.
- Runtime diagnostic metrics are limited to fixed-schema counters: `sifr.runtime.diagnostic.emitted` at accepted diagnostic emission with labels `surface="runtime"` and `level in {"trace","debug","info","warn","error"}`, and `sifr.runtime.diagnostic.rejected` before returning `DiagnosticError` for unsupported levels with labels `surface="runtime"` and `reason="unsupported_level"`.
- Metric labels intentionally exclude `diagnostic_target`, `diagnostic_name`, `diagnostic_message`, and rejected level text because those values are user-controlled, potentially sensitive, and high-cardinality. Duration histograms remain unimplemented until a future accepted runtime event has a concrete duration emission point and schema.
