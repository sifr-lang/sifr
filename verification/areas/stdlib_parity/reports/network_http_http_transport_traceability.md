# Network HTTP Transport Traceability: HTTP Core Transport

Status: implemented in HTTP-transport capability candidate branch.

| Requirement | network/HTTP baseline capability decision | Acceptance evidence |
| --- | --- | --- |
| HTTP/1.1 transport | Hyper-backed, Sifr-owned runtime wrapper, no client/server product API. | `verification/areas/runtime_platform/fixtures/http_transport_loopback.rs` runs as `http_transport_loopback_fixture` through `cargo test -p sifr_runtime --features http` and covers HTTP/1.1 TCP client/server loopback. |
| HTTP/2 transport | Hyper/H2-backed with Sifr resource/error wrappers. Default fixture body buffering is bounded to 1 MiB unless overridden. H2's automatic DATA-frame budget bounds small-frame overhead in production. | `http_transport_loopback_fixture` covers HTTP/2 h2c loopback with an absolute URI; runtime test `http2_settings_hpack_and_goaway_loopback` covers an explicitly constrained frame budget, SETTINGS negotiation, HPACK header roundtrip, and GOAWAY graceful shutdown; runtime test `http2_rst_stream_maps_cancel_reason` covers RST_STREAM cancellation mapping. |
| Typed request/response model | `sifr.http` substrate types from network/HTTP baseline and URL/header/cookie readiness; transport runtime coverage is verification-owned Rust, not a tuple-shaped Sifr harness. | Public `sifr.http` source behavior remains covered by `demos/network_http_substrate/main.sifr` for typed substrate construction; `http_transport_loopback_fixture` validates runtime request/response parts at the transport boundary. |
| Body streaming | Chunk type is built-in `bytes`; `collect_with_limit(max_bytes)` is accepted and unbounded collect is rejected. | `demos/network_http_substrate/main.sifr` covers Sifr-level chunked body construction and too-large body rejection without transport I/O; `http_transport_loopback_fixture` uses explicit request/response body bounds and verifies request/response limits are independent. Runtime test `client_request_and_response_limits_are_independent` also verifies the limits are not conflated. |
| HTTPS transport | consumes TLS capability TLS with ALPN. | `http_transport_loopback_fixture` covers HTTPS/H2 loopback with `h2` ALPN and the long-lived localhost fixture certificate. |
| Malformed protocol errors | malformed protocol input maps to typed `HttpError`/protocol evidence and must not panic. | Runtime test `http1_malformed_response_maps_to_typed_error` feeds an invalid HTTP/1 response and asserts a typed HTTP error string. |
| Server accept/dispatch/shutdown substrate | single-runtime-worker per process; the HTTP server framework owns framework routing and lifecycle product. | `http_transport_loopback_fixture` validates client/server connection ownership handoff without adding public server API. `sifr.http_transport` is not embedded, driver-seeded, or dependency-planned, so imports use the normal `SIFR-IMPORT-0002` unknown-module diagnostic. Serving-scale remains owned by `network-http-serving-scale-capability record` stable identifier `network-http-serving-scale-capability`. |
| HTTP/1 keep-alive | Deferred from the one-shot HTTP-transport capability loopback harness. | HTTP-transport capability forces `Connection: close` for HTTP/1.1 responses to keep single-connection substrate fixtures deterministic; network/HTTP readiness must record whether keep-alive remains deferred or add explicit keep-alive coverage before handoff. |
| Hyper-Util | conditional internal-only. | `verification/areas/stdlib_parity/reports/hyper_util_necessity.md` records Hyper-only adapter burden, selected `tokio` feature, and no public Sifr rules dependency. |
