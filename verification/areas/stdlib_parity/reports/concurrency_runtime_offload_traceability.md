## Capability Boundaries

Intentional post-blocking and CPU offload deferred boundaries:

- Full `WorkerError[E]` typing for homogeneous offload collections if the type system can preserve the user error parameter without nominal erasure.
- OS thread creation failure handling for `task.spawn_cpu` if the per-call `std::thread::spawn` bridge is replaced in future CPU bridge work.
- Process-global panic-hook mutation is no longer unsynchronized across generated CPU/Rayon surfaces: `sifr.parallel`, configured `Pool` work, `TaskScope`/`TaskGroup` scoped CPU offload, `task.spawn_cpu`, and `JoinSet.spawn_cpu` share one generated mutex around the temporary hook swap. Stable Rust exposes panic hooks as process-global state, so a fully per-thread hook is not available without a future runtime/crate decision.
- Top-level `sifr.parallel` calls now use a lazy private default Rayon pool held in generated `OnceLock` state and sized from `available_parallelism()`. If first construction fails, the generated `OnceLock` caches the typed runtime failure for the process lifetime. There is intentionally no mutable public shutdown/reconfiguration API; process teardown releases the private default pool.
