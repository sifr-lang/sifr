## M0 Resolved Decisions

| Decision | Outcome | Evidence |
| --- | --- | --- |
| mixed runtime owner | Use TaskGroup[E] as the canonical mixed owner; no distinct task.Scope/runtime.Scope is introduced in M0. | Server shutdown, process pump tasks, blocking offload, and CPU offload can be represented as typed child handles under TaskGroup or JoinSet without non-fail-fast scope semantics. |
| public task handle name | TaskHandle[T, E] is public; Task and BlockingTask remain internal/generated names only. | Existing generated lowering already treats task and blocking handles as affine observation handles. |
| observed TaskGroup failures | An explicitly awaited and statically handled child failure is observed and is not re-reported at group exit; unhandled child failure triggers fail-fast sibling cancellation and TaskGroupError[E]. | Matches the phase's static handled-failure proof while preserving deterministic fail-fast group exit. |
| race/select containers | race returns RaceResult { winner_index, outcome, loser_cancellations }; select returns SelectResult { branch_tag, outcome, loser_cancellations }. | Both use homogeneous result/error types unless the user supplies an explicit sum/enum type. |
| select syntax | select uses a compiler-known named-branch form task.select(name=awaitable, ...); keyword names are static branch tags. | Static branch identity is enforced without exposing runtime callback transports or event-loop objects. |
| scoped process handle shape | TaskGroup.spawn_process returns a distinct ProcessHandle that owns Child status observation plus stdin/stdout/stderr pipe access. | TaskHandle[Status, SubprocessError] would lose first-class pipe ownership; returning Child alone would blur supervision and observation. |
| offload error binding | TaskGroup.spawn_blocking/spawn_cpu require TaskGroup[WorkerError[E]] and align with JoinSet.join_all().await -> list[Result[T, WorkerError[E]]]. | Runtime worker failures and user E remain typed under one homogeneous group error type. |
| lock/permit await policy | Sync lock guards cannot cross await. Async lock guards are await-forbidden in M2 unless a specific guard is marked await-safe. Semaphore permits are guard-like: they cannot cross await and cannot escape through returns. | Prevents hidden shared mutable state and unbounded permit retention across suspension points. |
| Barrier and Once | Barrier is deferred-to-phase-X unless M2 finds a near-term production need; Once remains internal-only over std::sync::OnceLock. | Channels, locks, semaphores, and events cover near-term web/worker/data needs without toy public primitives. |
