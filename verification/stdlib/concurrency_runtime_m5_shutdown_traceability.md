# Concurrency Runtime M5 Shutdown Traceability

Milestone: `milestone_concurrency_runtime_5`

Status: In progress; signal value-model foundation covers portable `sifr.signal.Signal`, `sigint()`, `sigterm()`, `SIGINT`, `SIGTERM`, and `strsignal(signal)` evidence, structured signal stream shape/lowering now covers Ctrl-C and Unix SIGTERM shutdown waits, deterministic Unix signal-delivery evidence covers child-sent Ctrl-C, SIGTERM, and shutdown-stream waits, deterministic cleanup helper coverage includes no-value and value-carrying generic `sifr.resource.nullcontext(...)`, cleanup stacks and owned closing helpers are closed as unsupported diagnostics, task context value types are importable through `sifr.task.Context` / `ContextKey[T]`, explicit `TaskGroup(ctx=Context(...))` and `task.spawn_scoped(..., ctx=Context(...))` propagation is observable through `sifr.task.current_context()`, and structured runtime diagnostic events now lower to `tracing` behind Sifr-owned diagnostic types. Additional non-Unix signal delivery harnesses and metrics naming/cardinality policy remain M5 work.

## Production Surface Traceability

| Surface | M5 evidence | Notes |
| --- | --- | --- |
| `sifr.signal.Signal` | `signal_value_model_basic` | `Signal` is a Sifr-owned value with `name` and `number` fields. It is not CPython's `Signals` enum and does not expose raw host signal-handler mutation. |
| `sifr.signal.SignalError` | `signal_stream_shape_strsignal`; `lowers_signal_intrinsics_via_registry` | Typed error channel for host signal-listener failures. Non-Unix `terminate()` returns typed unsupported `SignalError` instead of claiming portable SIGTERM delivery. |
| `sifr.signal.sigint()`, `sifr.signal.sigterm()` | `signal_value_model_basic` | The first accepted signal factory helpers are portable shutdown targets. Unix-only values such as `SIGHUP` remain host-limited until a deterministic host row and fixture are added. |
| `sifr.signal.strsignal(signal)` | `signal_strsignal_basic` | Pure Sifr value helper returning the owned signal name. It does not consult process-global host signal state and does not claim stream delivery. |
| `sifr.signal.SIGINT`, `sifr.signal.SIGTERM` | `signal_constants_basic` | Portable module-level constants are importable Sifr-owned `Signal` values. They follow normal ownership rules and do not claim signal-stream delivery or process-global handler state. |
| `sifr.signal.ctrl_c`, `sifr.signal.terminate`, `sifr.signal.shutdown_stream` | `signal_stream_shape_strsignal`; `signal_stream_delivery_unix`; `lowers_signal_intrinsics_via_registry` | `ctrl_c()` and `terminate()` return awaitable `Result[Signal, SignalError]` values. `shutdown_stream().next()` waits for Ctrl-C or Unix SIGTERM and returns a typed `Signal`; non-Unix shutdown streams wait for Ctrl-C only. Runtime delivery is pinned through codegen lowering, nonblocking shape coverage, and a deterministic Unix fixture that sends delayed signals from a child shell to the current process. Non-Unix delivery semantics remain host-limited. |
| `sifr.signal.pause`, `signal.signal`, `getsignal`, `raise_signal`, `pthread_sigmask` | `signal_pause_unsupported`; `signal_handler_registration_unsupported`; `signal_getsignal_unsupported`; `signal_raise_signal_unsupported`; `signal_pthread_sigmask_host_limited` | Unsafe arbitrary handler registration, process-global signal wakeup, and mask mutation are not production APIs. Current evidence pins stable missing-member diagnostics on `sifr.signal` imports until a future explicitly supported surface is designed. |
| `sifr.resource.NullContext[T]`, `sifr.resource.nullcontext(...)` | `resource_nullcontext_basic` | `nullcontext()` remains a no-op helper whose entered value is `None`; `nullcontext(value)` now preserves the carried value type through the synchronous `with` protocol. Generated context-manager guards preserve generic type arguments for this value model. |
| `sifr.resource.ExitStack`, `sifr.resource.AsyncExitStack`, `closing`, `aclosing` | `resource_exitstack_unsupported`; `resource_async_exitstack_unsupported`; `resource_closing_unsupported`; `resource_aclosing_unsupported` | These helpers are explicitly diagnosed for this phase. Cleanup stacks must report cleanup failures under cancellation without hiding the initiating failure, and `closing`/`aclosing` require an explicit owned-close protocol before support. |
| Python `contextlib` convenience helpers: `redirect_stdout`, `redirect_stderr`, `chdir`, `suppress`, `contextmanager`, `asynccontextmanager` | `resource_redirect_stdout_unsupported`; `resource_redirect_stderr_unsupported`; `resource_chdir_unsupported`; `resource_suppress_unsupported`; `resource_contextmanager_unsupported`; `resource_asynccontextmanager_unsupported` | These CPython-shaped helpers are not production APIs in this phase. Generator decorator helpers require a future generator-semantics design, and process-global stdout/stderr/cwd mutation is rejected for production concurrent code. |
| `sifr.task.Context`, `sifr.task.ContextKey[T]`, `sifr.task.empty_context()`, `sifr.task.current_context()` | `task_context_value_model_basic`; `task_context_propagation_basic` | Importable Sifr-owned value model plus task-local read helper. `ContextKey[T]` carries a typed default marker so the key's value type is preserved without dynamic Python `contextvars` behavior. `current_context()` returns the explicit task-local label when a scope or spawn installed one, otherwise the default `Context`. |
| `task.TaskGroup(ctx=ctx)`, `task.spawn_scoped(..., ctx=ctx)` propagation | `task_context_propagation_basic`; `task_context_propagation_rejected`; M1 lowering unit tests | Non-`None` `ctx` values are accepted only for the Sifr `Context` value shape. `TaskGroup(ctx=...)` propagates to children spawned through the group, `task.spawn_scoped(..., ctx=...)` overrides the active owner context for that child, and non-`Context` values remain rejected. |
| `sifr.runtime.DiagnosticLevel`, `DiagnosticEvent`, `DiagnosticError`, `diagnostic_event`, `emit_diagnostic` | `runtime_diagnostics_tracing`; `lowers_runtime_diagnostic_intrinsic_with_tracing_metadata`; `runtime_module_dependency_metadata_includes_tracing_only` | Runtime warning-style events now use Sifr-owned diagnostic value types and typed `Result[None, DiagnosticError]` evidence. Codegen emits `tracing::event!` calls with fixed internal target `sifr.runtime` and structured `diagnostic_target`, `diagnostic_name`, and `diagnostic_message` fields. Generated projects include `tracing = 0.1.44` with `default-features = false` and `std` only when this surface is used; no `tracing` type leaks into Sifr source. |
| Python global `warnings` filter model | `warnings_filter_global_rejected`; M0/M0a negative import fixtures | Python warning filters remain rejected. Runtime warning-style events, if needed, must be structured diagnostics or tracing events. This closes the global-filter parity surface without introducing a `warnings` adapter. |

## Follow-up Boundaries

- `sigint()`, `sigterm()`, `SIGINT`, `SIGTERM`, and `strsignal(signal)` are value-model evidence only; awaitable `ctrl_c()`, `terminate()`, and `shutdown_stream().next()` now have Unix delivery evidence through delayed child-sent signals, while non-Unix delivery remains host-limited.
- Unsupported signal APIs are intentionally absent from `sifr.signal` so static imports produce stable diagnostics instead of runtime surprises.
- `pthread_sigmask` is grouped with unsupported signal APIs in the current fixture set because no safe mask-mutation surface exists; it remains host-limited for any future explicitly designed Unix-only API.
- `nullcontext()` is supported as a no-op cleanup helper and `nullcontext(value)` preserves the entered value type; cleanup stacks and owned closing helpers are closed as unsupported diagnostics in this phase until an owned-close protocol can preserve cleanup errors honestly.
- Additional non-Unix signal delivery harnesses remain future host-limited evidence before stream delivery can be marked fully portable.
- `Context`, `ContextKey[T]`, `empty_context()`, and `current_context()` are Sifr-owned context surfaces. Explicit propagation is label-based and immutable at the task boundary; Python `contextvars` dynamic mutation and implicit ambient request mutation remain out of scope.
- Structured runtime diagnostic events emit through `tracing`; metrics are not added in this wave because the phase requires concrete metric names, label/cardinality policy, emission points, redaction policy, and deterministic tests before selecting the `metrics` crate.
