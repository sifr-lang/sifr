# Supported Host Matrix

Status: active baseline for split production-stdlib substrate phases.

| Host Concern | macOS arm64 | Linux x86_64 | Windows x86_64 | Owner | Notes |
| --- | --- | --- | --- | --- | --- |
| Rust `String`/`str` text invariants | supported | supported | supported | text/i18n | Normal Sifr `str` is valid Unicode scalar text on every host. |
| Path byte/text boundary | host-limited | host-limited | host-limited | text/i18n + runtime | OS path interop that needs byte-preserving text is deferred to a separate issue; this phase does not smuggle invalid Unicode into `str`. |
| Binary file I/O prerequisite | supported | supported | supported | existing `sifr.io` owner | M0 smoke passes read/write/close/drop and byte-preserving round trips; file-handle seek/tell remains unsupported where not implemented. |
| Explicit text file I/O | blocked-on-text-i18n-m1 | blocked-on-text-i18n-m1 | blocked-on-text-i18n-m1 | text/i18n | Text `open(...)` requires explicit encoding and literal/static mode. |
| Host locale discovery | host-limited | host-limited | host-limited | text/i18n | Read-only `sifr.i18n.host_locale() -> Option[LocaleId]`; never supplies default text encodings. |
| ICU4X compiled locale data | planned | planned | planned | text/i18n | M3 records exact ICU4X components and supported data set. |
| Current-thread async task scheduler | supported | supported | supported | concurrency/runtime | Tokio remains internal and current-thread; no public runtime or event-loop handles. |
| Task/request context value model | supported | supported | supported | concurrency/runtime | `task_context_value_model_basic` validates host-independent `sifr.task.Context`, `ContextKey[T]`, and `empty_context()` values. This does not claim task-local dynamic state or propagation across task groups. |
| Explicit task/request context propagation | supported | supported | supported | concurrency/runtime | `task_context_propagation_basic` validates explicit `TaskGroup(ctx=Context(...))` inheritance, `task.spawn_scoped(..., ctx=Context(...))` override propagation, and `current_context()` default behavior. `task_context_propagation_rejected` still rejects non-`Context` values. Python `contextvars` dynamic mutation remains rejected. |
| Task/thread sendability and shareability diagnostics | supported | supported | supported | concurrency/runtime | M1 starts task-boundary enforcement; M2 extends it to channels and sync primitives. M3/M4/M6 extend it to offload, process, and IPC. |
| Channels, locks, semaphores, and async sync primitives | supported | supported | supported | concurrency/runtime | M2 validates bounded backpressure, close/drop wakeups, cancellation/no-loss receives, and lock/permit await rules as host-independent generated-runtime behavior; async lock surfaces remain deferred. |
| Blocking I/O offload | supported | supported | supported | concurrency/runtime | M3 validates `spawn_blocking_basic` and `join_set_spawn_blocking`/scoped offload coverage as host-independent generated-runtime behavior. Tokio blocking pool is internal; APIs expose typed WorkerError and no raw thread handles. |
| CPU parallelism | supported | supported | supported | concurrency/runtime | M3 validates `spawn_cpu_basic`, `join_set_spawn_cpu_join_all_ordered`, `parallel_map_basic`, `parallel_try_map_basic`, and `parallel_pool_map_basic` as host-independent generated-runtime behavior. Private Rayon pools only; default sizing uses available_parallelism(). |
| Subprocess spawning and termination | supported | supported | host-limited | concurrency/runtime | Unscoped sync/async spawn, wait, kill/terminate, pipes, status evidence, strict explicit text output, timeout TERM-to-KILL process-group cleanup, and scoped `TaskGroup.spawn_process` supervision have dedicated rows below. Non-Unix signal-equivalent status, terminate semantics, and Windows fixtures remain host-limited in those dedicated rows. |
| Sync subprocess stdout/stderr pipe readers | supported | supported | host-limited | concurrency/runtime | `process_spawn_pipe_readers` validates sync child stdout/stderr `PIPE` extraction and one-shot byte reads on Unix shell fixtures. Windows requires a deterministic fixture before marking supported. |
| Sync subprocess PipeReader streaming reads | supported | supported | host-limited | concurrency/runtime | `process_pipe_reader_streaming` validates bounded `PipeReader.read(max_bytes)`, EOF close behavior, invalid-size errors, and explicit reader close on Unix shell fixtures. Windows requires a deterministic fixture before marking supported. |
| Sync subprocess stdin pipe writers | supported | supported | host-limited | concurrency/runtime | `process_spawn_pipe_writer` validates sync child stdin `PIPE` extraction, repeated byte writes, and explicit close/EOF on Unix shell fixtures. Windows requires a deterministic fixture before marking supported. |
| Sync subprocess child handle cleanup | supported | supported | supported | concurrency/runtime | `process_child_resource_derives_are_module_scoped` verifies `sifr.process.Child` is a non-clone resource wrapper with generated `Drop` cleanup for unwaited sync child-table entries. | Async subprocess run/output loopback | supported | supported | host-limited | concurrency/runtime | `process_async_run_output` validates Tokio-backed async argv run/output and one-shot stdin-byte communicate on Unix shell fixtures. Windows process semantics are not rejected, but require a Windows-specific deterministic fixture before marking supported. |
| Async subprocess output timeout | supported | supported | host-limited | concurrency/runtime | `process_async_output_timeout` validates Tokio-backed stdout/stderr capture, one-shot stdin-byte communicate on completion, and kill/wait timeout status on Unix shell fixtures. Windows requires a deterministic fixture before marking supported. |
| Async subprocess spawn/wait | supported | supported | host-limited | concurrency/runtime | `process_async_spawn_wait` validates Tokio-backed `AsyncChild` spawn/wait, one-shot async wait observation, and stdin-byte rejection on Unix shell fixtures. Windows support requires deterministic follow-up fixtures before marking supported. |
| Async subprocess owned pipes | supported | supported | host-limited | concurrency/runtime | `process_async_spawn_pipes` validates `AsyncChild` stdin/stdout/stderr pipe extraction, repeated async writes, bounded async reads, EOF close behavior, explicit close, and typed closed-handle errors on Unix shell fixtures. Windows support requires deterministic follow-up fixtures before marking supported. |
| Scoped subprocess supervision | supported | supported | host-limited | concurrency/runtime | `process_scoped_spawn_handle` validates `scope.spawn_process(...)` / `TaskGroup.spawn_process(...)` returning `ProcessHandle` with owned async pipe access, explicit wait observation, typed repeated-wait errors, and unobserved successful child aggregation at scope exit on Unix shell fixtures. `process_scoped_parent_cancel` validates TaskGroup fail-fast parent cancellation stops a scoped child process before delayed side effects can escape. Windows support requires deterministic follow-up fixtures before marking supported. |
| Async subprocess kill/terminate | supported | supported | host-limited | concurrency/runtime | `process_async_child_kill_terminate` validates method-form `AsyncChild.kill()` forceful termination and method-form `AsyncChild.terminate()` Unix SIGTERM; `process_async_top_level_kill_terminate` validates borrowed top-level `async_kill(child)` / `async_terminate(child)` helpers. Windows terminate semantics remain host-limited until a deterministic Windows fixture and status mapping are added. |
| Sync subprocess graceful terminate | supported | supported | host-limited | concurrency/runtime | `process_child_terminate_wait` validates Unix SIGTERM request and subsequent `Status(kind=\"signal\", signal=15)` observation. Windows terminate semantics remain host-limited until a deterministic Windows fixture and status mapping are added. |
| Subprocess signal status evidence | supported | supported | host-limited | concurrency/runtime | `process_signal_status` records Unix `SIGTERM` exits as `Status(kind=\"signal\", signal=15)` through `std::os::unix::process::ExitStatusExt`; Windows signal-equivalent status mapping remains host-limited. |
| Subprocess strict text output encoding | supported | supported | host-limited | concurrency/runtime + text/i18n | `process_text_explicit_encoding` and `subprocess_text_explicit_encoding.sifr` validate sync argv and shell text output decoding through the text/i18n encoding substrate, including Latin-1 and `iso8859-1` aliases, with strict invalid-byte errors and no locale defaults. Windows requires deterministic fixture coverage before marking supported. |
| Shell subprocess execution effect | supported | supported | host-limited | concurrency/runtime | `process_shell_exec_output`, `process_async_shell_exec`, and direct-async diagnostic fixtures validate explicit shell execution, async shell status/output/timeout, `@shell_exec`, and blocking workload classification on Unix shell fixtures. | Signals and structured shutdown streams | supported | supported | host-limited | concurrency/runtime | `signal_value_model_basic`, `signal_strsignal_basic`, and `signal_constants_basic` validate the Sifr-owned `Signal` value model plus portable `sigint()`/`sigterm()` helpers, `SIGINT`/`SIGTERM` constants, and the host-independent `strsignal(signal)` helper. `signal_stream_shape_strsignal` and codegen tests pin awaitable `ctrl_c()`, Unix awaitable `terminate()`, `shutdown_stream().next()`, and both Unix/non-Unix lowering branches. `signal_stream_delivery_unix` validates delayed child-sent Ctrl-C, SIGTERM, and shutdown-stream delivery on Unix hosts. | Signal value model | supported | supported | supported | concurrency/runtime | `signal_value_model_basic` validates `sifr.signal.Signal`, `sigint()`, and `sigterm()` as portable Sifr-owned values; `signal_strsignal_basic` validates host-independent name rendering; `signal_constants_basic` validates importable `SIGINT` and `SIGTERM` constants. Windows support is by inspection of host-independent `.sifr` code only; this does not claim signal-stream subscription, signal delivery, or arbitrary handler support. |
| Deterministic cleanup scopes | supported | supported | supported | concurrency/runtime | `cancellation_cleanup_runs` validates timeout cancellation runs Sifr `finally` cleanup before the timeout error is observed, and `resource_nullcontext_basic` validates host-independent no-value and value-carrying generic `nullcontext(...)` through the synchronous `with` protocol. `resource_exitstack_unsupported`, `resource_async_exitstack_unsupported`, `resource_closing_unsupported`, and `resource_aclosing_unsupported` close cleanup stacks and owned closing helpers as diagnostics until cleanup-error and owned-close protocols are implemented. | Signal stream shape, lowering, and Unix delivery | supported | supported | host-limited | concurrency/runtime | `signal_stream_shape_strsignal` validates the public awaitable API shape, `lowers_signal_intrinsics_via_registry` pins Tokio Ctrl-C/SIGTERM lowering plus Unix/non-Unix cfg branches, and `signal_stream_delivery_unix` validates delayed child-sent Ctrl-C, SIGTERM, and shutdown-stream delivery on Unix hosts.
