# Supported Host Matrix

Status: active baseline for split production-stdlib substrate phases.

| Host Concern | macOS arm64 | Linux x86_64 | Windows x86_64 | Owner | Notes |
| --- | --- | --- | --- | --- | --- |
| Rust `String`/`str` text invariants | supported | supported | supported | text/i18n | Normal Sifr `str` is valid Unicode scalar text on every host. |
| Path byte/text boundary | host-limited | host-limited | host-limited | text/i18n + runtime | OS path interop that needs byte-preserving text is deferred to a separate issue; this phase does not smuggle invalid Unicode into `str`. |
| Binary file I/O prerequisite | supported | supported | supported | existing `sifr.io` owner | M0 smoke passes read/write/close/drop and byte-preserving round trips; file-handle seek/tell remains unsupported where not implemented. |
| Explicit text file I/O | blocked-on-text-i18n-m1 | blocked-on-text-i18n-m1 | blocked-on-text-i18n-m1 | text/i18n | Text `open(...)` requires explicit encoding and literal/static mode. |
| Host locale discovery | host-limited | host-limited | host-limited | text/i18n | Read-only `sifr.i18n.host_locale() -> Option[LocaleId]`; never supplies default text encodings. |
| ICU4X compiled locale data | planned | planned | planned | text/i18n | M3 records exact ICU4X components and supported data set. |
| Current-thread async task scheduler | supported | supported | supported | concurrency/runtime | Tokio remains internal and current-thread; no public runtime or event-loop handles. |
| Task/thread sendability and shareability diagnostics | supported | supported | supported | concurrency/runtime | M1 starts task-boundary enforcement; M2 extends it to channels and sync primitives. M3/M4/M6 extend it to offload, process, and IPC. |
| Channels, locks, semaphores, and async sync primitives | supported | supported | supported | concurrency/runtime | M2 validates bounded backpressure, close/drop wakeups, cancellation/no-loss receives, and lock/permit await rules as host-independent generated-runtime behavior; async lock surfaces remain deferred. |
| Blocking I/O offload | blocked-on-concurrency-runtime-m3 | blocked-on-concurrency-runtime-m3 | blocked-on-concurrency-runtime-m3 | concurrency/runtime | Tokio blocking pool is internal; APIs expose typed WorkerError and no raw thread handles. |
| CPU parallelism | blocked-on-concurrency-runtime-m3 | blocked-on-concurrency-runtime-m3 | blocked-on-concurrency-runtime-m3 | concurrency/runtime | Private Rayon pools only; default sizing uses available_parallelism(). |
| Subprocess spawning and termination | in-progress | in-progress | host-limited | concurrency/runtime | Unscoped sync/async spawn, wait, kill/terminate, pipes, status evidence, strict explicit text output, timeout process-group cleanup, and scoped `TaskGroup.spawn_process` supervision have dedicated rows below. Non-Unix status and termination semantics remain before this umbrella row can be marked supported. |
| Sync subprocess stdout/stderr pipe readers | supported | supported | host-limited | concurrency/runtime | `process_spawn_pipe_readers` validates sync child stdout/stderr `PIPE` extraction and one-shot byte reads on Unix shell fixtures. Windows requires a deterministic fixture before marking supported. |
| Sync subprocess PipeReader streaming reads | supported | supported | host-limited | concurrency/runtime | `process_pipe_reader_streaming` validates bounded `PipeReader.read(max_bytes)`, EOF close behavior, invalid-size errors, and explicit reader close on Unix shell fixtures. Windows requires a deterministic fixture before marking supported. |
| Sync subprocess stdin pipe writers | supported | supported | host-limited | concurrency/runtime | `process_spawn_pipe_writer` validates sync child stdin `PIPE` extraction, repeated byte writes, and explicit close/EOF on Unix shell fixtures. Windows requires a deterministic fixture before marking supported. |
| Sync subprocess child handle cleanup | supported | supported | supported | concurrency/runtime | `process_child_resource_derives_are_module_scoped` verifies `sifr.process.Child` is a non-clone resource wrapper with generated `Drop` cleanup for unwaited sync child-table entries. Dropping the wrapper abandons observation and drops the host child handle; it does not claim process kill, wait, process-group cleanup, or descendant supervision. |
| Async subprocess run/output loopback | supported | supported | host-limited | concurrency/runtime | `process_async_run_output` validates Tokio-backed async argv run/output and one-shot stdin-byte communicate on Unix shell fixtures. Windows process semantics are not rejected, but require a Windows-specific deterministic fixture before marking supported. |
| Async subprocess output timeout | supported | supported | host-limited | concurrency/runtime | `process_async_output_timeout` validates Tokio-backed stdout/stderr capture, one-shot stdin-byte communicate on completion, and kill/wait timeout status on Unix shell fixtures. Windows requires a deterministic fixture before marking supported. |
| Subprocess timeout process-group cleanup | supported | supported | host-limited | concurrency/runtime | `process_timeout_group_cleanup` and `process_async_timeout_group_cleanup` validate Unix timeout-launched children run in private process groups and timeout cleanup escalates TERM to KILL for background descendants before reaping the immediate child. Windows remains host-limited pending host-specific process-group or job-object design and deterministic fixture coverage. |
| Async subprocess spawn/wait | supported | supported | host-limited | concurrency/runtime | `process_async_spawn_wait` validates Tokio-backed `AsyncChild` spawn/wait, one-shot async wait observation, and stdin-byte rejection on Unix shell fixtures. Windows support requires deterministic follow-up fixtures before marking supported. |
| Async subprocess owned pipes | supported | supported | host-limited | concurrency/runtime | `process_async_spawn_pipes` validates `AsyncChild` stdin/stdout/stderr pipe extraction, repeated async writes, bounded async reads, EOF close behavior, explicit close, and typed closed-handle errors on Unix shell fixtures. Windows support requires deterministic follow-up fixtures before marking supported. |
| Scoped subprocess supervision | supported | supported | host-limited | concurrency/runtime | `process_scoped_spawn_handle` validates `scope.spawn_process(...)` / `TaskGroup.spawn_process(...)` returning `ProcessHandle` with owned async pipe access, explicit wait observation, typed repeated-wait errors, and unobserved successful child aggregation at scope exit on Unix shell fixtures. `process_scoped_parent_cancel` validates TaskGroup fail-fast parent cancellation stops the scoped process before a delayed marker write. Windows support requires deterministic follow-up fixtures before marking supported. |
| Async subprocess kill/terminate | supported | supported | host-limited | concurrency/runtime | `process_async_child_kill_terminate` validates method-form `AsyncChild.kill()` forceful termination and method-form `AsyncChild.terminate()` Unix SIGTERM; `process_async_top_level_kill_terminate` validates borrowed top-level `async_kill(child)` / `async_terminate(child)` helpers. Both preserve subsequent async wait observation and closed-handle typed errors on Unix shell fixtures. Windows terminate semantics remain host-limited until a deterministic Windows fixture and status mapping are added. |
| Sync subprocess graceful terminate | supported | supported | host-limited | concurrency/runtime | `process_child_terminate_wait` validates Unix SIGTERM request and subsequent `Status(kind=\"signal\", signal=15)` observation. Windows terminate semantics remain host-limited until a deterministic Windows fixture and status mapping are added. |
| Subprocess signal status evidence | supported | supported | host-limited | concurrency/runtime | `process_signal_status` records Unix `SIGTERM` exits as `Status(kind=\"signal\", signal=15)` through `std::os::unix::process::ExitStatusExt`; Windows signal-equivalent status mapping remains host-limited. |
| Subprocess strict text output encoding | supported | supported | host-limited | concurrency/runtime + text/i18n | `process_text_explicit_encoding` and `subprocess_text_explicit_encoding.sifr` validate sync argv and shell text output decoding through the text/i18n encoding substrate, including Latin-1 and `iso8859-1` aliases, with strict invalid-byte errors and no locale defaults. Windows requires deterministic fixture coverage before marking supported. |
| Shell subprocess execution effect | supported | supported | host-limited | concurrency/runtime | `process_shell_exec_output`, `process_async_shell_exec`, and direct-async diagnostic fixtures validate explicit shell execution, async shell status/output/timeout, `@shell_exec`, and blocking workload classification on Unix shell fixtures. Windows shell semantics require a deterministic fixture before marking supported. |
| Signals and structured shutdown streams | blocked-on-concurrency-runtime-m5 | blocked-on-concurrency-runtime-m5 | host-limited | concurrency/runtime | SIGINT/SIGTERM are the initial portable targets; Unix-only signals require host-specific rows and fixtures. |
| Deterministic cleanup scopes | blocked-on-concurrency-runtime-m5 | blocked-on-concurrency-runtime-m5 | blocked-on-concurrency-runtime-m5 | concurrency/runtime | ExitStack/AsyncExitStack cleanup reports typed evidence under cancellation. |
| Typed IPC frames over process pipes | blocked-on-concurrency-runtime-m6 | blocked-on-concurrency-runtime-m6 | blocked-on-concurrency-runtime-m6 | concurrency/runtime | Payloads require IpcSerializable; schema negotiation and malformed-frame behavior are M6-owned. |
| TCP sockets and DNS | blocked-on-network-http | blocked-on-network-http | blocked-on-network-http | network/HTTP | Text decoding must consume text/i18n M1. |
| TLS roots and certificate verification | blocked-on-network-http | blocked-on-network-http | blocked-on-network-http | network/HTTP | No local text fallback for diagnostics or IDNA. |
