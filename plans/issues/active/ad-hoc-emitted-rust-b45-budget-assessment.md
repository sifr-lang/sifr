### A — application-demand ownership and allocation lifetime

`crates/sifr_driver/src/stdlib/bootstrap.rs:117` canonicalizes each lowered
module, `:120` deep-clones it into an Arc-owned full HIR inventory, and `:325`

`lib_modules_and_codegen/deferred_codegen.rs:79` builds a local interop plan

`:404-406` retains files/features, while `:515-526` rebuilds the combined final
application plan. Moving selection only out of bootstrap would leave this

The demand owner `crates/sifr_codegen/src/stdlib_interop_demand.rs:206-214`
clones each visited function solely to use mutable visitors for read-only
analysis, then traverses it twice. At `:74-96` it clones each entire selected
module before discarding nonselected declarations. `:295-300` scans all
inventory functions for every intrinsic occurrence. `types.rs:6-129` recursively
walks full stored type/signature structure. The selected/pending declaration
sets deduplicate declaration expansion, not these temporary clones or repeated
type-resolution work. These are concrete allocation/traversal opportunities;
none is independently measured as the budget's numerical excess.

Minimal complete implementation proposal:

1. Give bootstrap/module-body emission an explicit result boundary that does
   not manufacture an application-demand plan. Compute the canonical selected
   plan once at final single-file or combined project assembly, before shared
   attachment/resolution. Do not infer this purpose from a module-name prefix
   or pass an empty inventory as a fallback. Preserve local codegen's structural
   policy and diagnostics and complete private inventory construction. Cover
   actual test-project consumers of the shared assembly without adding a lane.
2. Preserve the full checked inventory, but move completed HIR into its final
   owner after bootstrap consumers finish instead of cloning it while retaining
   the lowering result. Empty private modules must remain represented. Bootstrap
   views need only the metadata actually consumed by code generation, not the
   growing application-demand map. Share immutable inventory ownership across
   application codegen views; do not deep-copy bodies to perform read-only walks.
3. Add/reuse an exhaustive immutable type-and-expression visitor at the IR
   authority (`crates/sifr_ir/src/type_visit.rs` or a responsibility-specific
   sibling exported by `src/lib.rs`) so demand follows statement-only types,
   defaults and nested functions without cloning them. Project only selected
   declarations into the existing contract builder, avoiding whole-module
   clone-then-retain; retain all metadata that builder uses for nominal and
   structural identity. A per-inventory intrinsic lookup can replace repeated
   full scans; no general cache-key redesign or lossy type shortcut.
4. `stdlib/cache.rs:8-13` clones `StdlibCompiled` on every lookup;
   `bootstrap.rs:29-30` then throws away code/interop for `external_defs`.
   Provide a projection from the same success/error cache that clones only
   requested definitions. Preserve initialization and cached-error behavior.
   `stdlib/types.rs:6-11` and `stdlib_codegen_metadata.rs:6-31` own lifetime and
   sharing. Full HIR has real demand consumers: do not simply delete it, prune
   the global inventory by the first app, or claim this projection frees the
   still-live global inventory. A compact typed declaration graph would be a
   separate representation decision, not required by this assessment.
