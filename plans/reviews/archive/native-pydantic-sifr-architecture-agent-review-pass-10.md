## BLOCKER

### B-1 — Nothing owns build-time execution of the native verifier/emitter, and `check`-time program identity is unimplementable as specified

> **513–516:** "specialization produces a schema graph during check/build. A build-time `pydantic_sifr_core` compiler canonicalizes and verifies that graph and emits the deterministic immutable schema program"
> **520–521:** "The same schema program must have the same identity across `check`, `build`, `run`, tests, cache keys, and editor analysis."
> **636:** "Verification failures are package/compiler diagnostics."
> **62–63:** "invalid static schemas fail during **checking**/build rather than on the first production request"
> **664:** `pydantic_sifr_core` owns "build-time schema graph verification and immutable program emission"

Verification and canonicalization are assigned to the **Rust crate in the external repository** (664, 139), yet they must run at `check` time (520, 636, 62). But `sifr check` is frontend-only and never invokes cargo/rustc — `docs/cli_command_semantics.md:50`: `| \`sifr check <file>\` | frontend/type-check only | frontend/type-check only (file input) |`. Editor analysis (521) is further still from a cargo invocation.

That leaves exactly two escapes, and the document takes neither:

1. **The compiler hosts package-supplied native build-time code** (build-script/proc-macro-shaped execution during `check`, `emit`, `test`, and editor analysis). This capability appears in **no** owner list (187–200 lists "static data emission" and "specialization of generic package code" — neither is host execution of a package's Rust crate; 206–219 gives the package no compiler-invocation surface), **no** prerequisite row (1448–1453), **no** ps_1–ps_3 deliverable, and **no** exit gate.
2. **Canonicalization/verification is reimplemented in Sifr for `check`** — which directly violates **1737**: "No schema behavior is implemented independently in both Sifr and Rust."

This is not a wording fix. It is an unresolved design decision whose resolution changes ps_1–ps_3 scope (a new compiler capability plus its certification), and it would first surface at `ps_4` in the external repository — after all three compiler releases that were supposed to certify the substrate. ps_0's own gate at **1487–1488** forbids exactly this: "independent architecture review finds no unresolved **ownership**, semantic-authority, bridge, safety, or **sequencing** ambiguity."

## Can `milestone_ps_0` be re-approved?

**No.** Its exit gate (**1487–1492**) requires that review find "no unresolved ownership, semantic-authority, bridge, safety, or sequencing ambiguity" and that "every required feature family with a meaningful Pydantic oracle has pinned selector anchors". Five distinct classes of gate violation remain:

1. **Ownership** — nothing owns build-time native verification/emission at `check` and editor-analysis time (**B-1**), and the arena's governing certification row is unnamed while the named one excludes it (**MJ-9**).
2. **Required features with anchors but no design** — custom-error (**MJ-1**), the `now_op` clock (**MJ-7**), decimal precision constraints and string normalization (**MJ-5**).
3. **Substrate** — the enum node's value space is unbacked and no prerequisite adds it (**MJ-2**), while two substrate bullets still require a capability the accepted decision forbids (**MJ-3**).
4. **Sequencing** — ps_8's gate depends on ps_9 and ps_10 deliverables (**MJ-8**).
