Two findings from the M1 review — neither blocks the stated M1 acceptance tests (which all use sync stubs and successfully-parsed decorators), but both are worth addressing before the phase closes.

**1. Async Rust interop ellipsis stubs trip ASYNC_NO_SUSPEND** (annotations_and_function_lowering.rs:534). The pre-computed `async_suspension_summaries` treats an ellipsis body as `NoSuspend`, and the check fires before the stub is classified. M1's "bypass body-based checks" is only applied to `lower_stmts`, `requires_exhaustive_return_annotation`, and `infer_function_return_type`. The suspension check (and the sibling raw-AST `first_await_range_in_stmts`/`first_yield_range_in_stmts` passes) is not gated on stub status, so `@rust(...) async def foo() -> T: ...` emits a spurious "no real suspension effect" error. Sync stub tests don't cover this; async stubs will fail once M4 migrates any async stdlib surface.

**2. Malformed-Rust-decorator + ellipsis body double-reports** (rust_interop.rs:39). `has_rust_interop_declaration = !rust_interop.is_empty()` conflates "this is a Rust interop attempt" with "parsing succeeded." When the decorator name says `@rust` but arg parsing rejects the call (e.g. `@rust(Self.poll)` at module level, `@rust("...")`, `@rust(crate=..., path=...)`), the collector emits the correct malformed diagnostic and returns empty, and `classify_rust_interop_stub_body` then adds a misleading "ellipsis is only supported as the complete body of a Rust interop declaration" secondary. A name-level "is this decorator in the rust namespace?" check would silence the follow-up.

Both otherwise: helper decomposition is clean, all four function-like paths (top-level, nested, class/enum/newtype methods) call `classify_rust_interop_stub_body` consistently, `HirFunction.return_type` is preserved from the annotation via `ft.return_type.as_ref().clone()`, missing-return and return-inference are correctly gated on `stub_body.skips_normal_body_lowering()`, and `Expr::EllipsisLiteral` in `core_and_calls.rs:46` catches ellipsis leaking into expression positions (assign RHS, nested-if branches). Nested function inference safely produces `Type::Unknown` for ellipsis without corrupting inferred signatures. Test coverage matches the four stated M1 acceptance cases.
