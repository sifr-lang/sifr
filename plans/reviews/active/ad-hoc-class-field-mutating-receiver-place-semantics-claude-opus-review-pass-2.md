## Already partially implemented (the plan does not acknowledge any of it)

- **The receiver predicate already exists and already returns `true` for this case.** `method_call_needs_field_clone_suppression` (`crates/sifr_codegen/src/expr_render_helpers/field_and_stdlib_rewrites.rs:26`) returns `true` for any `Type::Class`-typed field receiver (line 40) and for any `self`-rooted field receiver (line 48). The defect is not a missing predicate — it is that the predicate is only consulted at **4 of the emit paths** (`stmt_expr_method_and_question_mark.rs:139`, `print_calls.rs:101`, `intrinsic_method_emitters/recursive_exprs.rs:150`, `string_char_cache.rs:745`), and the plain expression-statement method-call path that lowers `self.helper.bump()` never arms it. The plan's problem statement ("can lower the field read through the ordinary auto-clone path") is correct but misdiagnoses the shape of the fix.
- **The transport is an ambient decrementing counter**, `pending_self_field_clone_suppression` (`lib_emitter_state.rs:91`), consumed positionally in `lower_field_access_expr_with_lowered_object` (`field_and_stdlib_rewrites.rs:170`) by *whichever* qualifying field access is lowered next. Arm/disarm is hand-rolled at 7 sites with a `suppression_prev` guard. The plan's "explicit receiver access metadata" language implies replacing this, but never says so.
- **The mut-argument half already works** (M10) — `method_mut_arg_needs_field_clone_suppression` + fixture `crates/sifr/tests/e2e/pass/class_method_mut_borrowed_field_argument.sifr`. That fixture only asserts the *argument*-side mutation; the receiver side is untested, which is why the defect survived.
- **Receiver mutability inference already fires**, via `class_method_requires_mutable_self` → `body_contains_field_assign_codegen` → `is_self_field_mutating_method_call` (`helpers/helpers_impl.rs:639`), whose `Type::Class { .. }` branch treats *any* method call on a class-typed self field as mutating. `class_method_requires_mutable_self` is used at exactly one site — `class_method_emitter.rs:658`, signature emission — and never at the call site.
- **Parent-field re-rooting works** (`self.base.tag`), and **index/slice/optional receivers already fail closed** at type check. The plan's claim that they "generate invalid or silently detached Rust" is factually wrong on the current tree.

## Material gaps

**1. The core mechanism is undecided.** The plan says "explicit receiver access metadata … derived from the same convention metadata" but never says what that metadata is, where it lives, or what replaces the ambient counter. The two candidate designs have very different blast radii and the plan picks neither: (a) thread a `ReceiverAccess { Shared, Mut }` through the lowering call so `lower_field_access_expr_with_lowered_object` takes it as a parameter, deleting `pending_self_field_clone_suppression` and all 7 arm/disarm sites; or (b) mark the receiver on the HIR node in `sifr_lowering` (`HirExpr::MethodCall`) so codegen reads a field. This is the single largest unresolved choice.

**2. There is no receiver convention to look up.** `FunctionType` (`crates/sifr_type_system/src/types/definitions.rs:303`) has `params: Vec<(String, Type, ParamConvention)>` and **no receiver/self convention field**. `resolve_registry_method_params` (`intrinsic_method_emitters/plain_call_args.rs:401-430`) explicitly `skip`s the `self` param, and its two branches disagree about whether `self` is present at all (`func_signatures` branch returns params verbatim; the `Type::Class.methods` fallback computes `self_offset`). It also does not walk parents for inherited methods. The plan requires "derived from the same convention metadata" but that metadata does not exist. **Revision needed:** specify adding a receiver convention to the class-method signature record, populating it in `crates/sifr_lowering/src/lower/classes/class_body_lowering.rs`, and adding a `resolve_receiver_convention(object_ty, method)` that resolves through `func_signatures`, the class `methods` table, and the inheritance chain, with a stated behavior when lookup fails (conservative-mut vs. reject).

**3. Mutability roots for `self` are not modelled.** `class_body_lowering.rs:103/231/413` register `self` with `ctx.scope.define(...)`, not `define_parameter(..., is_mutable_binding)`. So `mut self` is never recorded, and `refill(self)` and `refill_explicit(mut self)` both infer `&mut self` today. The plan's "reject immutable roots" is therefore undefined for the `self` root. **Revision needed:** state explicitly that `self` receivers remain inference-based (never rejected), or that `mut self` becomes required — and if the latter, the migration for every existing fixture.

**4. Immutable non-`self` roots are not rejected and the plan does not say where the check goes.** `via_immutable_param(b: Box)` compiles today and silently loses the mutation. The existing gate, `reject_immutable_parameter_method_mutation` (`crates/sifr_lowering/src/lower/mutating_methods.rs:6`), is dead for this case because `is_collection_mutating_method` (line 82) returns `false` for `Type::Class`. **Revision needed:** name `mutating_methods.rs` as the owner, specify extending the predicate to class receivers with a mut receiver convention, and specify which of `SIFR-OWN-0005` (reuse) or a new code applies.

**5. Aliasing is specified at the wrong granularity.** The plan says "when the same **root** is also read by another argument." Root granularity over-rejects the legal `self.helper.soak(self.other)` (disjoint fields — `self.helper.soak(&self.other)` is valid Rust) and does not resolve the genuinely hard `self.helper.soak(self.helper)`. It also ignores that Rust two-phase borrows make `self.helper.soak(&self.helper.clone())` legal, so *retaining the argument clone* is a viable answer for the same-place case. **Revision needed:** state the rule as **place-prefix** comparison, not root comparison: disjoint field paths under a shared root are accepted with no clone; a receiver place that is a prefix of, equal to, or extends an argument's place is either (a) accepted with the argument clone retained, or (b) rejected with a named diagnostic. Pick one. Also state the rule for `mut` arguments (two `&mut` to overlapping places must be rejected — this is not the same rule).

**6. Nested-receiver clone placement is not specified.** The two nested shapes fail differently: `self.mid.inner` clones the intermediate hop, `self.base.tag` clones the leaf after parent re-rooting. A fix that only suppresses the leaf clone leaves `self.mid.clone().inner` broken. **Revision needed:** state that suppression applies to *every* hop from the mutability root to the receiver place, and that it composes with parent re-rooting in `field_and_stdlib_rewrites.rs:182-197`.

**7. Recursive fields are a distinct path.** `is_recursive_field` in `field_and_stdlib_rewrites.rs:204-249` has its own `Box`-aware returns (`take().map(|v| *v)`, `as_deref().cloned()`, `as_ref().clone()`) and honours `suppress_field_clone` only in the non-Option branch (line 205). A `Box<Self>` field receiver on the Option branch will still clone. The plan mentions "recursive" nowhere. **Revision needed:** state the intended emission for `Option<Box<Self>>` mutating receivers, or state explicitly that it is rejected.

**8. The emit paths to change are not enumerated, and the count is not 4.** The predicate is armed at 4 sites but the *statement/expression* surfaces that can host a mutating method call are broader: expression statements, `let`/assignment RHS (`lower_stmt/return_and_assignment_values.rs`), `return` (`return_lowering.rs`), `with` items, `try`/`?` (`stmt_expr_method_and_question_mark.rs`), comparison operands (`stmt_expr_wrappers_and_compare.rs:477`), operator protocol (`operator_rewrites.rs:132`), subscript aug-assign (`subscript_augassign_delete.rs:172`), and print args (`print_calls.rs:101`). The plan's "all statement/expression emit paths" is an aspiration with no list. **Revision needed:** enumerate the files, and state whether the fix is per-site arming (fragile) or a single choke point.

**9. Narrowing receiver mutability is a breaking change the plan does not budget for.** Fixing `read_only` to emit `&self` + no clone changes emitted signatures across the corpus, which cascades into caller-side `let mut` inference and the independent `MUTATING_METHODS` list in `ir_optimize/mutability_and_clone_rewrites.rs:4` (a **third** copy, disjoint from `hir_analysis/queries/queries_impl.rs:8` and the `helpers` re-export). Also `queries_impl.rs:482` tests `object.ty()` while `helpers_impl.rs:644` tests `resolve_alias_type_for_plain_call(object.ty())` — aliased class receivers behave differently. **Revision needed:** decide whether receiver-mut inference is narrowed in this change or deliberately left over-approximating; if narrowed, budget the snapshot churn and unify the three `MUTATING_METHODS` lists.

**10. No diagnostic codes are named, and the registry has hard requirements.** Every active code needs an entry in `crates/sifr_diagnostics/src/codes/registry/registry_entries/calls_flow_and_protocols.rs` with category, severity, message template, owning module, args **and a `representative_fixture_path` that must exist** (`registry_tests.rs:55`), plus a `docs/errors/SIFR-XXX-NNNN.mdx` page and a `docs/docs.json` nav entry — enforced by `scripts/check_docs_error_code_links.py` and generated by `sifr_diagnostics/src/bin/gen-error-docs.rs`. The plan says "stable diagnostics" and stops. **Revision needed:** name each code (next free is `SIFR-OWN-0014`), its message template and args, its owning module string, and its fixture path.

## Summary

The plan correctly identifies a real, reproducible, silent-wrong-result defect and correctly forbids depth-special-casing. But it is a scoping document, not an implementation plan: the central mechanism (explicit metadata vs. the existing ambient counter) is unchosen, the receiver convention it depends on does not exist in the type system, the aliasing rule is stated at a granularity that is simultaneously over- and under-restrictive, and diagnostics, test locations, file-size strategy, and validation are all unspecified. It also mischaracterises two areas of the current tree (indexed/optional receivers already fail closed; the suppression predicate already exists and already returns `true`).
