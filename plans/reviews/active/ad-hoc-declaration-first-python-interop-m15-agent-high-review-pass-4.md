## Actionable findings

### MAJOR 1 — Pass-3 MAJOR 2 is only partially closed: every non-trivial lockfile-less package still shows an editor error that `sifr check` contradicts

`graph_independent_no_python_package` (`crates/sifr_lsp/src/python_declarations.rs:443-467`) exempts only the trivially-empty shape (no deps, no dev-deps, no `[python]`, no trust, no artifacts, no bridge inventory). Every other lockfile-less shape still reaches `load_package_graph_snapshot(..., CargoLockMode::Frozen)` (`:333-343`), and `cargo metadata --frozen` fails (empirically re-verified, exit 101) on any tree without `Cargo.lock`, rendering a persistent `SIFR-PACKAGE-0101` **error** on the owner document. `sifr check` uses `CargoLockMode::Normal` (`crates/sifr/src/cli_model_and_entrypoint.rs:679-690`), writes the lockfile as a side effect, and passes cleanly on the same tree — for:

- `[dependencies]` non-empty, zero Python anywhere;
- `[python]` config with no declarations (`selects_environment()` disables the skip);
- any package with `@python` declarations (`required_import_roots` non-empty disables the skip — even stdlib-only ones like `math`, which check's library-deferral path passes).

Concrete failure: clone any Sifr package that doesn't commit `Cargo.lock` (one dependency or one declaration suffices), open it in the editor before ever running a CLI command → red package error; `sifr check` passes. This is the exact acceptance-criterion-1 violation pass 3 flagged, minus one shape. The single new test (`lockfile_less_package_without_python_inputs_has_no_editor_diagnostic`, `python_declaration_tests.rs:419-440`) covers only the fixed sliver. Structurally, widening the predicate cannot fix the deps-bearing shapes (the graph is genuinely needed to see dependency-contributed Python requirements) — the residual fix must reconcile the Frozen-vs-Normal load itself (e.g. a non-mutating metadata strategy, or downgrading/suppressing this specific failure with a "run sifr check once" hint), plus tests for the deps/config/declaration shapes. Mitigating: the state self-heals once a lockfile exists, because `Cargo.lock` is fingerprinted and the fingerprint is recomputed per request.

### MAJOR 2 — The skip predicate introduces a new anti-conservative parity break: bridge sources without the generated inventory JSON silently lose validation the compiler performs

The predicate keys on **file existence** of `src/python_bridges/__sifr_inventory__.json` (`python_declarations.rs:464-466`), but check does **live discovery**: `resolve_python_bridge_graph` → `discover_python_bridge_inventory` scans `src/python_bridges/*.py` from the filesystem with no JSON required (verified first-hand: `crates/sifr_package/src/python/bridge_inventory/mod.rs:48-98`, `crates/sifr_package/src/python/bridge_resolution.rs:104-146`), and bridge third-party imports feed `required_imports` → `requires_python = true` → trust/environment validation (`crates/sifr_package/src/python/environment.rs:168-174`). Scenario: a zero-dep app package where the author adds `src/python_bridges/util.py` importing `numpy` before generating the inventory — `sifr check` fails trust/environment validation; the LSP satisfies the skip predicate and **silently shows nothing**. Because the skip short-circuits before the graph load unconditionally, this misfires even on trees **with** a lockfile — it is not scoped to the situation it was meant to fix. Introduced by 75a0d97b2 (pre-fix LSP always resolved and would have shown the trust error); untested. A narrower sibling: in a cargo workspace, a zero-dep member skips on its own root manifest while check aggregates `[python] requires-imports` and non-root selections across all graph members (`crates/sifr_package/src/python/requirements.rs:43-58`, `selection.rs:66-95`). Fix direction: the skip must also check the bridge-source *directory* (not just the inventory file) and account for workspace-member aggregation — or simply be restricted to packages where the graph itself is degenerate.

### MINOR 3 — Skip/cache inputs are not all fingerprinted, so the cached skip can go stale for a session

`package_input_fingerprint` (`python_declarations.rs:594-626`) hashes root `Cargo.toml`/`Cargo.lock`/`sifr.toml`, both authoring artifacts (including absence), selected pyproject/uv.lock, and interpreter metadata — but **not** the bridge inventory the skip predicate consults, bridge `.py` sources, or dependency packages' manifests. Creating the inventory/bridge sources without touching a fingerprinted file leaves the cached empty snapshot (`:233-244`) served until an `invalidate_external` watcher batch arrives — and the server never registers file watchers itself, so recovery depends on client defaults that typically don't cover generated `.json` under `src/`. Pass 3 ledgered the dependency-manifest half as an accepted watcher-dependent trade-off; the fix widened the unfingerprinted surface by making a **decision input** (inventory existence) invisible to the key. Add the bridge inventory (existence + content) to the fingerprint at minimum.

### MINOR 4 — The Wave-3 cancellation claim is unobservable in production, and external probes have no timeout

`LspServer::run` processes messages strictly sequentially on one thread (`crates/sifr_lsp/src/server.rs:68-117`) with requests handled inline, so a `$/cancelRequest` can only be read *after* the current request returns — the inter-probe `check_active_request_cancelled` (`python_declarations.rs:266`) can never fire mid-request in production; the only test marks the request cancelled manually before calling in (`python_declaration_tests.rs:550-572`). Combined with no timeout on any `Command::output()` (cargo metadata, environment probe, one `python -I -c` per target, one `importlib.metadata.version` per certified distribution), a hung interpreter wedges the entire server, including shutdown. Additionally, every watcher batch unconditionally calls `invalidate_external` + republish (`session.rs:147`), re-running `cargo metadata` + the environment probe synchronously even for non-Python dep-bearing packages. The single-threaded shape is pre-existing and was accepted in passes 1–3, but those passes accepted it believing the cancellation checks were live; the Wave-3 checkbox ("honor request cancellation around external probes") and the architecture doc's cancellation claim are met only at the API level. Either wire cancellation observation (reader thread feeding the cancel set) plus subprocess timeouts, or temper the claim in the plan/doc.

### MINOR 5 — Package-diagnostic ownership transitions leave stale or vanished diagnostics

Package-scoped diagnostics attach only to the deterministic min-URI owner (`python_declarations.rs:298-308`). Closing the owner clears its diagnostics and schedules nothing for the new owner (`crates/sifr_lsp/src/notifications/mod.rs:174-200`) — a still-true package error silently disappears until the sibling is next republished; the converse (opening a smaller URI) transiently duplicates the diagnostics across two files. Relatedly, single-document publishes don't refresh sibling documents whose python diagnostics depend on whole-workspace state (e.g. the `compiler_has_errors` gate), and an internal error from the python snapshot aborts publication of already-computed ordinary compiler diagnostics for that document (`diagnostics.rs:136-154`). All self-heal on the next publish trigger; fix by republishing the new owner on close and isolating snapshot errors from compiler-diagnostic publication.

### MINOR 6 — Shared-target merged rejection: cross-kind message attribution and untested fan-out paths

The OR-merge fix is correct at the accept/reject level (see disposition below), but on a mixed-flag rejection the single merged diagnostic is cloned onto **every** declaration targeting the path (`crates/sifr_driver/src/build/python_interop.rs:290-309`; LSP spans at `python_declarations.rs:478-515`), so a plain function declaration can be shown "invalid Python opaque declaration: target … is not a Python type" — worded for a sibling declaration kind, with no hint the constraint is inherited. Only the first violated merged constraint produces a message (main emitted one per violated probe). Both new tests use `plan.declarations = []`, so the per-declaration attribution path on merged rejection, the mixed-flag *success* path, and an end-to-end LSP mixed-flag scenario are all untested. CLI output is unaffected (recovery dedup collapses the clones).
