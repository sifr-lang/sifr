## Blocking finding — flaky M13 evidence suite in the blocking merge gate

`crates/sifr/tests/python_read_only_cli.rs` (new in this diff) fails nondeterministically under default parallel execution. Reproduction: repeated `cargo test -p sifr --test python_read_only_cli` failed 3 of 6 runs here (`4 passed; 2 failed` each time), with rotating victims and three distinct symptoms — `uv lock fixture should succeed` (line 52), `secondary application directory should be written: AlreadyExists` (line 36), and `application entrypoint should be removed: NotFound` (line 251). All three are cross-test fixture-directory sharing: the fixture root is `temp_dir()/sifr-python-readonly-{label}-{pid}-{SystemTime nanos}` (lines 70-77), four tests share the label `application` and the pid, and I measured that `SystemTime::now()` here has only **microsecond** granularity (all inter-thread deltas were multiples of 1000 ns) — I reproduced a same-nonce collision directly with a standalone program that mimics the fixture (spawn `uv --version`, then take the nonce; collision in round 1 of 8). `create_dir_all` at line 78 then masks the collision, so two tests silently share one root, race `uv lock`, and one test's `Drop` deletes the other's fixture. Sibling fixtures (e.g. `build_output_behavior.rs`) avoid this by using a per-test `{name}` in the path; this file does not.

This matters because the suite runs inside `sifr_cli_full` (`cargo test -p sifr -- --skip test_e2e_pass`), a blocking, `executed_in_merge: true` step selected by `crate_tests: "full"` in the **merge, nightly, and release** profiles (`verification/profiles/merge.json:350`, `nightly.json:345`, `release.json:344`), and it is also the documented unit-test command in AGENTS.md. The fix is small and test-only: give each test a unique fixture label (or add a process-wide atomic counter to the nonce) and replace the masking `create_dir_all` with `create_dir` so a future collision fails loudly; then demonstrate repeated parallel stability.
