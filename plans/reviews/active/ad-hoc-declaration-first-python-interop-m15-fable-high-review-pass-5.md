## Disposition of every pass-4 finding

**MAJOR 1 (lockfile-less parity break) — CLOSED.** The remediation abandoned the structurally-incapable skip predicate, exactly as pass 4 demanded: the graph now always loads (`python_declarations.rs:333-336`), and only Cargo's specific missing-lock/frozen failure is converted into a read-only deferred status (`missing_lockfile_frozen_failure`, `python_declarations.rs:445-457` — requires `Cargo.lock` absent at the cargo invocation directory **and** a Command-kind failure whose output names the lock file). Empirically verified on cargo 1.94.0 across missing/stale/malformed/workspace shapes. `lockfile_less_nontrivial_packages_defer_without_mutation` (`python_declaration_tests.rs:443-509`) covers precisely the three shapes pass 4 listed — dependency-bearing, configured-environment, and declaration-bearing — asserting empty diagnostics, `pythonStatus == "deferred"` in completion, and that `Cargo.lock` is never created; all three fail on the pass-4 code. `stale_existing_lockfile_remains_a_package_error` (`:575-595`) pins the non-suppression side. The residual divergence direction (lockfile-less package with real Python requirements: editor shows deferred, `sifr check` writes the lockfile and then errors) is a deliberate, documented policy — "A missing Cargo lock is never created by the editor: the Python status remains deferred until ordinary package resolution creates it" (`internal_docs/python_interop_declaration_architecture.md:618-621`) — and is conservative: nothing is promoted, the status is honestly `deferred`, and the state self-heals once any package operation materializes the lock. Hardening nits remain (below), none reopening the finding.

**MAJOR 2 (skip predicate anti-conservative) — CLOSED.** The predicate is deleted outright, so the bridge-source and workspace-member blind spots are structurally dead: `resolve_python_bridge_graph` (live discovery, no inventory JSON required) and workspace-member requirement aggregation always run once the graph loads (`python_declarations.rs:362-364`). Both missing scenarios now have discriminating regressions: `live_bridge_sources_without_inventory_are_validated_and_fingerprinted` (writes `src/python_bridges/util.py` importing numpy with **no** inventory JSON and **no** watcher event, asserts `SIFR-PYTRUST-0005`) and `workspace_member_python_requirements_are_validated` (member `[python] requires-imports` surfaces on the root document).

**MINOR 3 (unfingerprinted skip/cache inputs) — CLOSED.** `hash_python_bridge_inputs` (`python_declarations.rs:619-649`) recursively hashes the bridge tree — paths, contents, and error kinds for absence — into `package_input_fingerprint`, which is recomputed per request, so bridge edits invalidate without watcher help (pinned by the no-watcher-event assertion in the live-bridge test). The decision-input concern is moot (the predicate no longer exists). The dependency-manifest half remains the pass-3-ledgered watcher-dependent trade-off, unchanged.

**MINOR 4 (unobservable cancellation claim, no probe timeouts) — CLOSED via the tempering option pass 4 offered.** The architecture doc now states "Cancellation state is checked at scheduler boundaries and between probes when it is observable; the sequential server does not preempt an already-running external process" (`python_interop_declaration_architecture.md:621-624`), and the Wave-3 checkbox was reworded to "check **already-observed** cancellation" (`plans/issues/active/ad-hoc-declaration-first-python-interop.md:2101-2103`) — both now accurate against `server.rs`'s sequential loop.
