Reviewed the M7b sync process child/pipe migration against the six-item checklist. No blocking findings.

**Verifications passed**
1. Public API preserved. `sifr.process` still exports Child/PipeReader/PipeWriter with their prior methods, and `spawn/kill/terminate/wait` at top-level (`stdlib/sifr/process.sifr:154-203, 417-452`). Status shape is preserved via `_status_from_parts` consuming the 3-int `[code, signal_value, has_signal_flag]` list.
2. Child Drop is rewired but semantics match. The emitted `Drop for Child` (`crates/sifr_codegen/src/class_emitter.rs:24-72`) still guards on `!self._waited` and now calls `sifr_stdlib::process::process_child_close(SifrIntBridge::from(self._handle))`, which does `process_children().remove(...)` (`crates/sifr_stdlib/src/process/child.rs:64-66`). Compared with the prior preamble, this is functionally identical (map removal only, no reap). No new zombie leak vs. prior behavior. `process_wait` also removes before waiting (`child.rs:47-53`), so if `_waited` is set-then-fail the child is already gone.
3. No sync child/pipe intrinsics remain in the registry (`crates/sifr_codegen/src/intrinsics/registry.rs:29-304` only contains `process_async_*`/`process_handle_wait`), the retained catalog (`internal_docs/stdlib_retained_compiler_intrinsics.toml:189-210` `_sifr.process` lists only async names + `preamble_files` no longer includes `process_child_pipes.rs`), or the preamble emission/filter path (`crates/sifr_codegen/src/stdlib_filter/implementation.rs:265-444` — sync child/pipe static/fn names are gone; only async statics/fns and `__sifr_process_exit_signal` remain). `registry_extended_tests.rs:238-293` pins these as `.is_none()` from the registry.
4. Async process behavior untouched: `process_async_*` remain in the retained-intrinsic surface (`sifr_retained_intrinsics/src/process.rs`), registry, preamble filter, and public `sifr.process` re-exports. `preamble/process_runtime.rs` is trimmed to the still-needed `__sifr_process_exit_signal` helper used by async decoding.
5. No new panic paths. All native functions use `Mutex::lock().unwrap_or_else(std::sync::PoisonError::into_inner)`, `usize::try_from(max_bytes)` is bounded by the 1 MiB check first (`child.rs:141-150`), and `handle_value` goes through `to_i64_saturating`.
6. Dependency assumptions are valid. `SifrIntBridge::From<i64>` exists (`sifr_runtime/src/interop.rs:89-93`), and `sifr_stdlib::process::process_child_close` is re-exported (`sifr_stdlib/src/process.rs:16-21`). Codegen only emits the Drop when the current module is `sifr.process`, which already forces `sifr_stdlib` linkage via the process feature.
