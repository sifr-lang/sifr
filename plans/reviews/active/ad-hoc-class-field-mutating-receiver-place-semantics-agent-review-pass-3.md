## Remaining blockers

**1. `Place.root: BindingId` rests on infrastructure that does not exist, and the facts it needs are gone by the time validation runs.**
`grep -rn BindingId crates/` returns **zero hits**. Scope is name-keyed `HashMap<String, VarInfo>` frames (`crates/sifr_lowering/src/scope.rs:101`, `196-240`) with no binding identity, and frames are pushed/popped per function (`scope.rs:131,136`). §2 requires conventions to converge only *after* class bodies are lowered, and validation to run after that — at which point the scope state that decides root eligibility (parameter vs owned local, `is_mutable_binding`, `own` vs borrow, `self`-with-`MutableBorrow`) no longer exists. Required: state the concrete root-identity mechanism (introduce an id in `Scope::define_binding`/`VarInfo` and expose it through `lookup`, or define root identity as `(frame depth, name)` captured at call-lowering time), state that root eligibility facts are captured onto the method-call node during lowering so the post-pass validates without scope, add `crates/sifr_lowering/src/scope.rs` to the anchors, and note that `Type::Class.fields: Vec<(String, Type)>` (`crates/sifr_type_system/src/types/definitions.rs:145`) carries no declaring-class data, so `field_identity` must be resolved by walking `ctx.class_types` parents. This is also what makes Item 1 non-independent as written: it fixes the HIR node shape, so the capture decision must land in Item 1, not Item 2.

**2. The post-fixed-point ordering is not reconciled with how flow effects are actually recorded.**
Effects are recorded inline during lowering (`ctx.record_flow_effect`, `crates/sifr_lowering/src/lower/mutating_methods.rs:74`) and consumed once at `crates/sifr_lowering/src/lower/mod_impl.rs:814`; class bodies lower before module function bodies inside `lower_module_bodies` (`mod_impl.rs:797`). Required: state that the fixed point runs between class-body and module-function lowering, and state whether receiver-derived mutation/borrow effects for calls inside class bodies are re-emitted by the post-pass or patched — §6 currently assumes effects can consult a convention that is not final when they are recorded.

**3. Non-class receivers are unspecified while "missing metadata is an ICE" is absolute.**
§1 requires every source method call to carry a resolved convention and forbids codegen defaults; §2 makes unknown metadata an internal compiler error. But builtin/stdlib receivers (list/dict/set/str/bytes, file and socket handles, `Task`/`JoinSet`/iterators, Python-opaque, Rust-opaque, `TypeVar`-bound, unions) have no receiver metadata today — only a ~40-name untyped list (`crates/sifr_codegen/src/hir_analysis/queries/queries_impl.rs:8`). Required: state the resolution rule for non-class receiver types and the explicit conservative outcome when the canonical table has no entry (i.e. `SharedBorrow` + today's value path), and state whether place validation/`SIFR-OWN-0014` applies to builtin `MutableBorrow` receivers at all — verified today `make().append(3)` compiles cleanly, so a blanket unsupported-place rule newly rejects it.

**4. §6's "one canonical type-and-method query" is infeasible for the pass that actually decides `let mut`.**
`crates/sifr_codegen/src/ir_optimize/mutability_and_clone_rewrites.rs` runs on untyped `RustExpr`/`RustStmt` (invoked at `crates/sifr_codegen/src/entrypoints.rs:159`), and it both classifies mutation by method name (`:447`) and **demotes `let mut` → `let`** (`:100-116`). It cannot call a type-and-method query. Required: specify the mechanism — export a single canonical method-name set for that untyped pass, or have codegen record the locals the place emitter requires to be mutable and exempt them from demotion — and state that user-class `MutableBorrow` receivers are covered.

**5. Mutable protocol receivers are broken today, and none of the emitters that must change are in scope.**
Verified on the supported protocol shape (`own mut entity: Bumper`, `def bump(mut self)`): the generated trait signature is `&self` (`crates/sifr_codegen/src/type_emitters.rs:21`) while the impl is `&mut self`, so the bridge `Helper::bump(self)` leaks `error[E0308]` via `SIFR-BUILD-0005`. Separately, `lower_type_emitter_method_item` (`type_emitters.rs:286`) contains a **second** receiver-mutability inference (`body_contains_field_assign_codegen`) that will silently diverge from the canonical convention, contradicting the "sole source for Rust `self` signature" criterion. Required: add `type_emitters.rs::emit_protocol_trait`, `type_emitters.rs::lower_type_emitter_method_item` and `operator_protocol_emitters.rs::emit_protocol_impls` as anchors; require every `RustParam::SelfParam { mutable }` site to derive `mutable` from the convention or state why it is fixed; and pin the mandated protocol pass fixture to the `own [mut] param: Proto` shape — borrowed protocol-typed parameters fail to coerce to `Box<dyn _>` today (verified, pre-existing and unrelated), so the fixture must not depend on them.

**6. Three mandated `SIFR-OWN-0014` fixture rows are unreachable.**
Verified: `slots[0].bump()` and `part[0].bump()` (list index/slice) fail earlier with `SIFR-STDLIB-0001` because index results are optional-typed, and `self.maybe.bump()` under `if self.maybe is not None` also fails with `SIFR-STDLIB-0001` — field optionals are not narrowed. So "indexed receiver", "sliced receiver" and the field-narrowed optional row cannot produce `SIFR-OWN-0014`, and the registry's `representative_fixture_path` (`unsupported_indexed_mutating_receiver.sifr`) names an unreachable shape while `registry_tests` requires the fixture to exist. Reachable shapes verified today: a narrowed **local/parameter** optional (`maybe: Helper | None` currently emits `if let Some(mut maybe) = maybe.as_ref()` and leaks `E0596`) and a temporary/call-result root (`Helper().bump()`, `make().bump()` compile). Required: move index/slice/field-narrowed rows into the "existing `SIFR-STDLIB-0001` boundary" statement §3 already makes for un-narrowed optionals, keep `SIFR-OWN-0014` fixtures to the reachable shapes, and rename the registry fixture accordingly.

**7. `FunctionType` `self`-in-params inconsistency blocks argument footprint alignment.**
Class-method signatures sometimes include `self` in `params` and sometimes not: `resolve_registry_method_params` computes a `self_offset` (`crates/sifr_codegen/src/intrinsic_method_emitters/plain_call_args.rs:414-421`) while `reject_immutable_method_mut_borrow_arguments` zips args straight onto `signature.params` (`crates/sifr_lowering/src/lower/mutating_methods.rs:57`). §4 makes the same overlap function validate method arguments by convention, so alignment must be pinned. Required: state that adding `FunctionType.receiver` normalizes `self` out of instance-method `params` (naming the consumers to update), or state the offset rule the validator must apply.
