### B-2 — `SIFR-INT-0009` cannot be emitted by any mechanism this design defines, and no milestone owns it

> **1033-1034:** "An absent or insufficient profile fails at compile time with `SIFR-INT-0009`, including path, boundary, static range, and suggested policy."
> **1835** (ps_9), **1910-1912** (acceptance): the same requirement.

Four independent facts make this unimplementable as written:

1. *Fix:* name the detecting verifier, add a `ps_1`-or-`ps_2` compiler deliverable that activates `SIFR-INT-0009` (or defines the general mechanism), and add the missing-profile case to **700-714**.

## Can `milestone_ps_0` be re-approved?

**No.** Its exit gate (**1658-1663**) requires that independent review find "no unresolved ownership, semantic-authority, bridge, safety, or sequencing ambiguity", that "every required feature family with a meaningful Pydantic oracle has pinned selector anchors", and that an omitted upstream file or collected node be "mechanically detectable". Five classes remain:

1. **A failing gate.** The change set's own certification row breaks `check_tiers.py` and the area runner (**B-1**), and the area is outside `scripts/run_all_tests.sh`, so the authoritative facade would not catch it.
2. **An unimplementable requirement.** `SIFR-INT-0009` is reserved, unemittable by the only channel the design defines, and unowned by any milestone in either repository (**B-2**), making acceptance criterion **1910-1912** unachievable.
3. **An incoherent frozen baseline.** The two pins are six minor versions apart; a public string constraint in the API oracle has no engine in the designated core oracle; "the pinned `string.rs`" is ambiguous between two differing files; and the core-table caption resolves silently in the wrong tree (**B-3**).
4. **Semantic authority and ownership.** The diagnostic channel collides with an accepted implemented contract and three accepted rules (**MJ-1**); the integer-profile divergence is undocumented and the locked artifact's update obligation is unowned across a repository boundary (**MJ-5**); the bounded-integer schema row is missing (**MJ-6**); the Phase 41 supersession orphans a deliverable, dangles two `completed`-phase deferrals, and deletes the phase's Quality Contract (**MJ-7**); the durable row enumeration is now factually wrong (**MJ-8**).
5. **Algorithms and coverage.** Smart-union clauses 2-4 misdescribe the pin and two ranking rules have neither a clause nor a discriminating anchor (**MJ-2**); `left_to_right` is a mandatory anchor with no node (**MJ-3**); the `decimal_whole_digits` counting basis is refuted and the code has no anchor (**MJ-4**).

**Where the design stands.** The conformance machinery is finished and now clean for a fifth consecutive pass — total-set ledger with explicit roots and a recorded vendored exclusion, multiplicity-aware parameter identity, the `Selection` overlay algebra (verified line-by-line against `filter.rs` with one scoping error), 294 unambiguous singly-owned anchors, and 52/52 in-milestone gating. Both pass-11 blockers are closed at the root, both minors are fully closed, and `isize`/`usize` is closed subtractively and completely. The architecture proper remains sound: trait-bounded monomorphized structural calls under a bridge version correctly acknowledged as absent (`rust_interop_architecture.md:303` documents v1 only; `sifr_fields.rs:311-318` rejects `version != 1`; `rust_interop_bridge_contract.rs:489` still rejects `TypeVar`), Core Schema as sole *package* authority with an explicit deference carve-out, the validated arena with no third tree, crate-neutral specialized-scalar payloads, Python-free `jiter`, and the external-repository split with the canonical demo owned externally (all 11 demo mentions mutually consistent, and the ps_1–ps_3 sequencing verified coherent).

The failure mode has shifted from "the document says something the pin refutes" to **"the fix landed on the contract but not on the owner, the anchor, or the arithmetic."** Five of pass-11's eight items are `PARTIAL` for exactly that reason: MJ-1 has all four artifacts but no reconciled code/URL/severity model; MJ-2 has the profiles but no policy entry and no artifact owner; MJ-4 has the error name but the wrong counting basis and no anchor; MJ-5 has the redirect but three untransferred obligations; MJ-6 has the row but a broken tier assignment. Three additions would convert this class into a checkable one: **(a)** require every newly-named diagnostic code, matrix row, or verification artifact to name the repository, file, and milestone that creates it — which would have caught B-1, B-2, and MJ-8 mechanically; **(b)** require every stated error code to name the anchor whose assertion observes *that code*, not merely its module — which would have caught MJ-4(d) and MJ-2's nested-bubbling gap; and **(c)** resolve the pin pair to a single engine authority with a stated rule for one-sided behavior, since as frozen the baseline cannot answer "which `string.rs`?".
