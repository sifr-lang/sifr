## Findings

**A. Ownership enforcement for the close member is module-local, while the finding-6 fix makes cross-module close calls emit.** `collect_rust_opaque_close_methods` scans only the current module's top-level `ClassDef`s (`crates/sifr_lowering/src/lower/rust_interop.rs:26-64`, called at `mod_impl.rs:72`), so `ctx.rust_consuming_methods` is empty in a consumer module. Both new guards keyed on it — the borrowed-receiver rejection and `mark_moved_with_flow` (`methods_lambdas_and_comprehensions.rs:226-245`) — are therefore inert for an imported opaque class, whose methods still type-check because `ExternalDefs` carries the class `Type` with its methods (`external_defs.rs:14-20`). Repro shape: module `resources` defines the round-6 `Resource`/`close=close`; module `main` does `from resources import Resource` and `def close_it(resource: Resource)` → `resource.close()`. `sifr check` reports nothing; the owner module emits `fn close(self)` in the now-`pub` trait, `main` imports it (`lib_project_codegen.rs:80-97`) and emits `resource.close()` on `&Resource` → E0507. Two calls → E0382. This is round-6 finding 3's defect class, unmoved, on the path finding 6's fix just opened; the new guard test (`lib_project_codegen.rs:292-338`) asserts only the rendered import text, not that the cross-module program compiles.

**B. The new Closed/Poisoned mapping emits an untyped error whenever the declared error class isn't message-shaped.** `opaque_self_receiver` routes both arms through `bridge_declared_error_expr` (`rust_interop_direct.rs:147-152`, `:158-162`), which falls through to `bridge_error_contract_expr`; that returns the **raw value unchanged** when `message_error_fields` rejects the class — i.e. whenever any field is non-`Str` or no field is named `message` (`rust_interop_error_mapping.rs:100-113`, `:254-270`). So for `class ResourceError(Error): detail: str` (or `message: str` + `code: int`) on an opaque class with `@rust(Self.ping) def ping(self) -> Result[str, ResourceError]`, the Closed arm emits `Err("Rust handle is closed")` (a `&str`) and the Poisoned arm `Err(__sifr_stored_panic)` (a `RustPanicErrorBridge`) where `ResourceError` is required → E0308, after a clean `sifr check`. Nothing in `rust_opaque_validation.rs` constrains the error class shape — it only requires `Result[...]`. Code-read, not executed. The pre-diff `self._handle.…` body was also broken (E0609), so this is not a regression, but it does mean question 4's "correctly typed" holds only for the message-shaped subset the fixtures happen to use.

**C. The Result-only guard in `self_method_call` converts a driver diagnostic into a compiler panic for non-opaque `Self.*` methods.** `rust_interop_direct.rs:122-124` now returns `None` for a non-`Result` return type. `validate_rust_opaque_close_method` early-returns for non-opaque classes (`rust_opaque_validation.rs:9-14`), and `parse_target_path` allows a `Self.` root on any *method* owner regardless of opacity (`lower/rust_interop.rs:535-543`) — the opacity requirement is enforced only later, in the driver, at `rust_interop.rs:336-366`, which runs on the plan **after** codegen. So:

```python
class Tok:
    @rust(Self.encode, panic=trusted_no_panic)
    def encode(self, text: str) -> str: ...
```

`rust_interop_method_body` → `None` → the ellipsis stub lowers to an empty body → `panic!("class method IR lowering produced empty body for non-unit return: Tok::encode")` (`class_method_emitter.rs:722-731`). Pre-diff this same source emitted `self._handle.encode(text)` and surfaced the clean `SIFR-RUST-RESOLVE-…` unresolved-root diagnostic. With `-> None` instead, the method silently emits an empty body. Either way the guard needs to be a diagnostic (or the `Self.`-root/opacity check needs to move into lowering), not a codegen `panic!`.

**D. The bridge contract synthesizes a receiver param for `Self.*`-targeted opaque methods that forward no receiver.** `signature_contract` adds the `self` param for *every* `MethodKind::Regular` method of a class present in `catalog.opaque_classes` (`rust_interop_bridge_contract.rs:172-190`; catalog registers all methods, `:296-309`), including `Self.`-rooted ones. Codegen takes the `root == SELF_ROOT` branch and passes no receiver argument (`rust_interop_direct.rs:84-98`). The contract is consumed only for generated types, unsupported-type diagnostics and the plan cache key (`rust_interop.rs:751-760`, `cargo_manifest.rs:180`), so this doesn't reach rustc — but it is a published contract that misdescribes those signatures, and `stdlib_async_resource_lifecycle.sifr:11-15` is exactly this shape (`@rust(Self.aclose)` with `own self`, now claimed as an `Own`-convention `Handle<…>` bridge parameter that no bridge function takes).

**E. The borrowed-close rejection matches only plain `Name` receivers.** `methods_lambdas_and_comprehensions.rs:228-239` guards `if let HirExpr::Name`, and `mark_moved_with_flow` is name-keyed (`mod_context.rs:453-471`) with no attribute-move tracking. A handle held as a field (`self.resource.close()` from a `&self` method, or `wrapper.resource.close()` on a borrowed `wrapper`) consumes out of a borrow with no diagnostic → E0507. Same-class-of-defect as A, lower likelihood; this mirrors the pre-existing `python_consuming_methods` limitation, so it is a scope gap rather than a regression — but it is unstated in `internal_docs/rust_interop_architecture.md:208-216`, which claims borrowed close receivers are rejected before rustc.
