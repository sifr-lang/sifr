# M11 Arrow C Data Interface — full milestone review (PR #2991, `main...HEAD`, 103 files, ~5,000 insertions)

## Verdict

**Not satisfied.** The architecture is fundamentally right — one nominal `Type::PythonArrow(kind)` variant reuses the entire hardened M10 affine machinery via `contains_affine_resource`; the runtime never calls Arrow `release` itself and delegates exact-once release to validated PyCapsule destructors; moves are committed at `prepare_arrow_argument` before the consumer runs; certification is fail-closed everywhere it applies. But there are reproduced compiler panics from check-clean programs, a class-method ownership downgrade that makes the milestone's own "owned consumer" shape un-declarable, and a certification chain whose no-copy "proof" is asserted rather than measured. These violate the milestone's acceptance criteria and the "if it compiles, it works" contract.

## Blockers

**B1 — Check-clean programs ICE in codegen (three shapes, reproduced against the branch binary).**
- `@python(pkg.f)` with `own value: python.ArrowArray = python.omit` → `check` clean, `emit` panics `SIFR-INTERNAL-0001` at `crates/sifr_codegen/src/function_emitter/generator_bodies.rs:398`. I reproduced this personally.
- `@python.coroutine` with an owned Arrow parameter → same check-clean panic (also semantically wrong: `PythonArrowArray` is `!Send` and coroutine wrappers cross the loop thread).
- `mut own value: python.ArrowArray` on a `@python(Self.m)` method → check-clean panic at `class_method_emitter.rs:709`.
Root cause: `crates/sifr_lowering/src/lower/python_interop/direct_validation.rs:44-58` accepts `Type::PythonArrow` parameters without excluding `omit_when_absent`, async declarations, or method shapes, while only the sync function body builder (`python_interop_direct.rs:196-212`) has an Arrow argument path. Remediation: reject all three shapes in `validate_direct_parameters` with PYZC diagnostics.

**B2 — Class methods silently downgrade `own` on Arrow parameters; opaque owned consumers are impossible.** `class_method_param_convention` (`crates/sifr_lowering/src/lower/classes/parameter_conventions.rs:5-22`) keeps `own` only for must-use types, and `must_use_obligation_for_type` (`mod_context.rs:250-283`) has no `PythonArrow`/`PythonBuffer` arm. Consequences: `@python(Self.push)` with a written `own value: python.ArrowArray` is rejected with "must transfer ownership with `own`" — a dead-end diagnostic the user cannot satisfy, so the most common consumer shape (e.g. a writer method taking a table) is un-declarable; and a plain class method taking `own a: python.ArrowArray` that calls `a.release()` passes `check` and fails in rustc (E0507), because `ctx.borrowed_params` is never populated for method parameters. This defeats the M11 task "Implement owned argument transfer" for methods and breaks check⇒compile. Remediation: preserve declared `own` for affine types in the convention resolver, populate `borrowed_params` in class-method lowering as `lower_function` does, and fix the diagnostic.

**B3 — Same-statement double consumption passes `check`.** `consume2(value, value)` and `consume2(v, take(v))` compile-check cleanly and fail only at rustc (E0382), because owned-argument consumption marking runs after all arguments are lowered (`regular_calls.rs:458-472`) and `consume_owned_value` (`core_and_calls.rs:589-610`) ignores the already-moved bool. Every cross-statement/branch/loop/container variant is correctly rejected; only the single-call window is open. Pre-existing for `python.Buffer`, now inherited by all five Arrow kinds — it directly violates the M11 "use-after-move" acceptance item. Remediation: emit `OWN_USE_AFTER_MOVE` when `mark_moved_with_flow` reports a prior move within the same call.

**B4 — The no-copy certification chain does not prove, bind, or fully enforce what the milestone requires.**
- The reference fixture (`verification/.../python_certifications/arrow_evidence.py`) is tautological: `pointer_identity_verified` compares two `PyCapsule_GetPointer` reads of the same capsule (lines 61-65 — true for any capsule, including a copying export), and `copy_performed: False` / `exact_release_count: 1` are hardcoded literals (lines 116-118). A copying producer certifies cleanly. Evidence is fixture-self-attested end-to-end (`python_cli.rs:302-338` accepts the booleans verbatim, never verifies the fixture honored the target passed in `argv[1]`).
- `ArrowCertification` (`crates/sifr_package/src/python/arrow_certification.rs:18-29`) has **no Arrow-kind field**: a stream-export certification of a producer authorizes array/device acquisitions of the same type. Runtime enforcement then flattens further to a global `(producer_module, producer_type)` set (`python_runtime.rs:257-280`, `arrow_ops.rs:179-194`), so a certification recorded for target B is honored when target A returns that producer type.
- `@python.arrow(Self, ...)` methods bypass build-time certification and schema-mode gating entirely: the interop plan collector never pushes method declarations (`crates/sifr_codegen/src/python_interop_plan.rs:109-140` — only the class's Opaque declaration), so the driver loop at `python_interop.rs:82-119` never sees them; only the coarse runtime producer check applies. (This corrects my earlier interim note — the `Some(["Self"])` target never reaches that loop.)
This combination fails "Require executable no-copy certification tied to the exact producer… never certify uncertain copying." Remediation: measure buffer-address identity in the fixture (e.g. `pyarrow` `Buffer.address` vs the exported `ArrowArray.buffers[i]`), echo target+kind in the evidence JSON and reject mismatches, add `kind` to the artifact and check it at build, key runtime admission per-declaration, and collect Arrow method declarations into the plan.

**B5 — `sifr python certify` and the build compute different environment digests; the declaration-first workflow deadlocks fail-closed.** Certify resolves with no derived requirements (`python_cli.rs:120` → `resolve_python_environment`, which is `_with_requirements(&[])`, `environment.rs:81-86`), while the build adds declaration- and bridge-derived requirements (`check_and_package_commands.rs:170-192`). The digest serializes the whole probe request including import roots (`digest_build_cache.rs:29-35, 93-100`), so for any package whose Python roots are declaration-derived (the M2/M3 design intent), certify writes digest D1, the build computes D2 ≠ D1 and rejects the artifact — unrecoverable except by manually duplicating every derived root in `[python].requires-imports`. The arrow-examples lane masks this by writing `requires-imports = [pandas, polars, pyarrow]` into its generated manifest (`example_packages.py:296-306`). Remediation: build the certify probe request exactly as `package_compiler_context` does.

**B6 — The "borrowed" requested-schema parameter is consumed by conforming real producers, with no reconciliation and no real-producer coverage.** Lowering enforces the schema parameter as an immutable shared borrow (`python_interop/arrow.rs:132-138`), but `clone_requested_schema` (`arrow_ops.rs:296-314`) passes the *original live capsule* as `requested_schema` — and PyArrow's `__arrow_c_array__`/`__arrow_c_stream__` call `Schema._import_from_c_capsule(...)` → Arrow C++ `ImportType`, which moves the struct and NULLs `release` (I verified this in the pinned venv's pyarrow 22.0.0 sources). After one call the still-"live" Sifr `ArrowSchema` is hollow: reuse yields a confusing producer error, `release()` becomes a silent no-op, and a later owned transfer of it is misclassified `Consumed` → `Ok`. No memory unsafety (destructors no-op on NULL release), but the affine borrow contract is broken producer-dependently. The only test uses a mock producer that doesn't consume (`arrow_ops/tests.rs:96-112`), the shipped fixture can only ever emit `schema_mode: "omitted"`, and no compiled/live case exercises `schema=parameter` — despite the milestone's explicit "Requested-schema omitted/parameter shape, certification, and mismatch fixtures." Remediation: either make the schema parameter consuming at the type level, or deep-copy the schema into a fresh self-owned capsule per export, or at minimum inspect the schema struct post-call and hard-error/mark-consumed on producer consumption; then add real-producer parameter-mode fixtures.

**B7 — Required evidence and ledger completeness gaps.**
- `verification/areas/python_interop/declaration_capabilities.json` (arrow row) still says `implementation_status: "reserved"` with every evidence row `"planned"` while all shipped docs declare Arrow active — the M0 machine-readable capability matrix, reported in every verification run, contradicts the delivery.
- Bridge-producer acquisition has **zero** tests or fixtures anywhere (milestone requires `Self` / import-root / bridge fixtures; M10 shipped the bridge analogue).
- The compiled example (`arrow_declaration_compiled.sifr`) covers acquisition+release of array/stream with omitted schema only — no owned transfer to a real consumer, no failure/rollback in a compiled binary, no schema kind, no `schema=parameter`, no device kinds (mock-only, unlabeled in the evidence JSON).
- `arrow_declaration_evidence.json` gets only JSON-well-formedness validation (`run.py:440-455`), versus the M10 buffer evidence validator with owner-existence, marker cross-checks, and mutation self-tests; its `covers` line already overclaims bridge coverage.
- Codegen tests skip `ArrowSchema`/`ArrowDeviceArray`/`ArrowDeviceStream` in every producer shape, multi-owned-argument ordering, and keyword-only owned arguments.

## Non-blocking findings

**Major**
- *Capsule payload deref lacks an alignment check* (`abi.rs`, every `pointer.cast::<T>().as_ref()`): a Python-level capsule with a misaligned/undersized payload named `arrow_schema` reaches a misaligned `&ArrowSchema` — Rust-side UB. Within the `[trust].python` envelope (trusted Python can already corrupt the process via ctypes), so hardening rather than a new capability: add `addr % align_of::<T>() == 0` rejection and document the trust boundary.
- *`sync_event` never validated* (`abi.rs:152-202`): CPU-type device arrays must have `sync_event == NULL` per the Arrow device spec; garbage non-null values pass "validated" acquisition. The milestone's "device metadata" validation item is incomplete.
- *Certified distribution versions are not re-verified at build time* (`package_python_certifications.rs:7-33`): if the producer distribution isn't a probed import root, `pip install -U` inside the venv leaves the digest unchanged and a stale version certification is accepted.
- *New keyword-only class-method parameters drop declared defaults* (`class_body_lowering.rs` / `class_type_collection.rs` kwonly loops): `def add(self, *, extra: int = 5)` then `c.add()` → spurious "missing required argument". A general half-capability shipped beyond Arrow's needs.
- *`copy_possible` semantics silently inverted on the retained raw API*: the pyarrow/polars allowlist was removed and `producer_info` now hardcodes `copy_possible: true` (`arrow_ops.rs:596-604`). Directionally correct (certification replaces the compiler allowlist), but `arrow_capsule_contract.json:10,17` still records `expected_copy_possible: false` (now factually wrong) and the internal-doc sentence citing `copy_possible` as evidence is stale; the raw-API behavior change is undocumented.

**Minor**
- Device-type allowlist accepts undefined values 5 and 6 (`abi.rs:324`) — should be `[1,2,3,4,7..16]`.
- `certify arrow` executes the fixture before containment validation; `--fixture ../outside.py` runs (nothing persists, but the invariant is enforced post-execution) — apply `safe_fixture_path` + symlink checks before `run_fixture` (`python_cli.rs:155-172`).
- All `Self` Arrow methods would share the single certification key `"Self"` if collected (fold into the B4 rework: key by opaque class target).
- `PythonArrowArgument` lacks a `Drop` reconciliation: early `?` exits skip `finish()`, deferring capsule release to the next GIL attach and transiently skewing `live_objects` accounting (release remains exact-once).
- CLI polish: success output ignores `--message-format json`; every failure maps to `SIFR-PYZC-0001` including environment errors; artifact write is not temp+rename; `sifr package` dry-run never validates the artifact; fixture TOCTOU windows.
- Test hygiene: `reset_runtime_state_for_tests` doesn't drain `ARROW_STORE`; `arrow-examples` lane timeout (600s) can be exceeded by its own subprocess budgets.

**Nits** — dead `foreign` flag makes `PythonArrowX::acquire`/`acquire_with_schema` unreachable, untested public API (`python_arrow_codegen.rs:57-104`); unsubscripted `python.Buffer` now gets an Arrow-flavored error message; positional-only `self` yields a wrong-reason receiver diagnostic; `update_object_count` called under the `ARROW_STORE` guard fixes a lock order the buffer path shares.

## What is verifiably solid

Exact-once release architecture (release delegated exclusively to validated capsule destructors; every failure path single-release; moved-remains-moved committed before the consumer runs; partial-consumption cleaned then errored); GIL/lock discipline (all Python work under `attach`, no Sifr lock held across Python, no lock-order inversion); capsule validation (byte-exact names, non-null payloads, `release==NULL` rejected at acquisition, pair child/dictionary consistency, tuple arity); no user-reachable panics in the runtime module (checked arithmetic, fallible accessors, no `extern "C"` unwind surface); canonical nominal identity (no basename matching — a user class named `ArrowArray` gets no Arrow semantics); the full M10 affine negative matrix holds for Arrow across branches, loops, closures, containers, unions, generics, generators, walrus, min/max, match, and task scopes; certification persistence (path/symlink/traversal safety, SHA-256 fixture binding, env-digest binding, sorted-unique targets, `deny_unknown_fields`, archive inclusion, cache-key participation with a rebuild test); root-only authority (dependencies can never execute or certify); `--check` is genuinely read-only; both new lanes are fail-closed (no silent skip) and wired into all four profiles; the 11/11 CPython-3.11 lane is exact-set-locked; all new files respect the 900-line guardrail; non-Arrow lowering changes are diagnostic-string-only ("buffer"→"resource"), with no behavioral regression found.

## Note on the passed validation gates

The 674/674 / 261 / 20/20 / 11/11 results are real but blind to every blocker above: the ICEs and check/rustc divergences occur in declaration shapes no fixture exercises, the schema-consumption defect is invisible to mock producers, and the digest deadlock is masked by the harness writing `requires-imports` explicitly. Closing B1–B7 requires adding exactly the fixtures the milestone text already lists.
