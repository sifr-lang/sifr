# Remaining Actionable Refinements

- **Bridge-to-bridge import rewriting is implicit.** The bridge-loader spec covers ordinary `import` and `from ... import ...` for third-party Python roots but does not explicitly say what happens when one bridge module in the same package imports another (e.g. `from bridge import helpers` inside `identifiers.py`). Reserved-namespace rewriting must apply to those internal references too, or the M4 loader will surface `ModuleNotFoundError` at runtime. One sentence in "Bridge Module Registration" naming this case (rewritten under the same `__sifr_bridge__.p_<key>` prefix and captured in the embedded source table) would close it.
- **`M3` and `M4` implicit prerequisite on `M1`.** M3 typed conversions and M4 bridge handles both consume the sealed handle representation introduced in M1, but neither milestone lists that dependency. A one-line "Depends on M1 handle representation" entry under each would make the ordering unambiguous for reviewers picking up the phase mid-flight.
- **`close=drop`, `close=close`, `close=async_close` decorator-argument grammar.** The architecture uses bare identifiers (`drop`, `close`, `async_close`) as decorator kwarg values. Ruff's Sifr parser accepts them as `Name` expressions, but the lowering rule that treats them as a closed policy atom set (rather than resolving them as ordinary Sifr identifiers) is not spelled out. A one-line note in "Minimal Decorator Grammar" that these are literal policy atoms consumed by lowering, not name-resolved, prevents surprises later.
- **N1 comparison to Rust opaque is now partially answered** ("Rust-specific clone, borrow, and sync policies" intentionally omitted) but the reasoning could still call out the GIL/single-interpreter rule as the reason `sync=` is absent. Optional prose polish.

Nothing above is worth blocking this documentation PR; each can be folded into the M0 lock commit or a follow-up doc pass without redesigning any subsystem.

# Final Contract In One Paragraph
Sifr Python interop keeps its embedded root-owned uv/CPython environment, structured `PythonError` results, `@blocking_io` classification, non-send objects, and explicit zero-copy contract, and adds a declaration-first authoring layer on top. Package authors write ellipsis-only Sifr functions and `@python.opaque` classes decorated with `@python(dotted.path)`, `@python.attr(Self.name)`, or `@python.item`, where the Sifr signature is the sole conversion contract; targets are structured paths rooted in either a source-declared Python import (whose presence in a decorator both declares the requirement and triggers deferred probing under root trust), the reserved `bridge.*` root for package-local Python modules embedded under `__sifr_bridge__.p_<package_key>` and served by a first-position runtime `MetaPathFinder`, or `Self` for opaque methods. Fixed positional and keyword-only parameters map to Python positional args and named kwargs; `*args`, `**kwargs`, and record expansion are rejected in v1. Probes resolve as verified, runtime-checked, or rejected. Raw `sifr.python.Object` and every `@python.opaque` value lower to one sealed compiler-owned handle whose drop detaches from the object store before releasing the GIL and either decrefs immediately on attached threads or hands off to a runtime pending-release queue drained at every attach and at generated-program epilogue, never panicking in user paths. Ordinary reference release is compiler-managed and distinct from semantic `close=close`/`close=async_close` or protocol release/shutdown. Records lower to plain Python dicts outbound and, inbound, prefer attribute lookup before string-key item lookup while ignoring extras — preserving today's `py_from_record`/`py_copy_record_fields` semantics. Static import roots and bridge imports contribute inferred requirements; `[python].allow-imports` is retired atomically in M6 with `SIFR-PYTRUST-0002` retired and `SIFR-PYTRUST-0005` covering an inferred root not authorized by the root application, while `[python].requires-imports`, `[trust].python`, and `[trust].python-native` remain the root-owned authorities. Stub-assisted `sifr python bind` never produces `py.Object`/`Any`/bare `object`/`Callable[..., Any]` fallbacks and stamps every generated declaration with a SOABI + distribution-version + source-precedence + stub-hash fingerprint that `--check` compares without rewrites. Diagnostic families `SIFR-PYIMP-0001`, `SIFR-PYCALL-0001`, `SIFR-PYCONV-0001`, `SIFR-PYRES-0001`, `SIFR-PYZC-0001`, and `SIFR-PYCB-0001` are reserved in M0 with fixed meanings. The phase ships across M0–M11 as small reviewable PRs — contract lock, IR + sealed handles, opaque model, value conversions, hermetic bridges, ecosystem migration, environment/manifest authority migration, read-only check/doctor, symbol-selective binding generation, LSP support, and finally advanced-protocol design followed by implementation plus a closeout that requires named compiled-Sifr live cases (Redis, Postgres, Kafka, direct SQS, SNS→SQS) with executable positive and negative evidence per supported capability.
