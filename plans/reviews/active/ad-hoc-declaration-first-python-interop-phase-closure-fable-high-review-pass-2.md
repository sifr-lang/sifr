## Part 2 — New findings

### BLOCKER

**NB-1 — `@python` decorators on nested defs are silently discarded; the B1 defect class survives one indentation level down.**
`crates/sifr_lowering/src/lower/statements/statement_dispatch.rs:682-873`: the nested-`FunctionDef` arm never calls `collect_python_interop_declarations` or the stub classifier, hard-codes `python_interop: Vec::new()` (line 868), and its decorator collection keeps only bare-`Name` decorators — a call-form `@python(...)` vanishes with no diagnostic at any stage. **Reproduced by me at HEAD:** a nested `def compute` under `@python(math.sqrt)` with a real body — `sifr check` prints `no errors found`, and the built binary runs the *Sifr body* (`value=123`, Python never called). The ellipsis-body variant fails, but with the wrong family (`SIFR-TYPE-0012: ellipsis is only supported as the complete body of a Rust interop declaration`). Nested *Rust*-interop declarations are collected on this same path (line 784), so the omission is an oversight, not a design decision. This violates the locked "declaration bodies are ellipsis-only" decision and M0's one-syntax-one-contract rule identically to pass-1's B1 — the same decorated `def` means two things, silently resolved (this time in Sifr's favor). Pre-existing, not introduced by the remediation — but this is a whole-phase review and the surface is in scope.
**Remediation:** collect and classify python decorators on nested defs (either activating them with full validation or rejecting them with a stable PYCALL diagnostic); add nested-def negatives for both real-body and ellipsis forms.

### MAJOR

**NM-1 — The M7 fix breaks introspection-based binding of same-module class-typed signatures (regression introduced by this commit).**
`python_binding_probe.py:63-64` now returns the full dotted annotation, but `python_binding.rs:235-239` matches only bare same-invocation class names, with no module-prefix normalization. The runtime-introspection fallback renders every non-builtin class as `module.QualName`. **Reproduced by me:** binding a plain module (`class Client`, `def use(c: Client) -> int`, no stubs — ordinary class-object annotations) now fails with `SIFR-PYCONV-0001 … 'plainpkg.Client'`; the same bind succeeded before the fix via leaf matching. Self-qualified string annotations (`"mypkg.Client"`) fail identically. `bind --check` re-probes recorded bindings, so previously checked-in artifacts of this shape would newly fail as pseudo-drift. Fail-closed is the right direction, but this rejects the *correct, most common* case, not just the foreign one.
**Remediation:** normalize/accept qualifiers equal to the bound module (and its aliases) before the class-name check, keeping the foreign-qualifier rejection; add a same-module qualified positive fixture.

**NM-2 — `WorkerRuntimeError` exit-cause misclassification (regression introduced by this commit).**
The basename-shadowing hardening in `outcome.rs:20-23` and `sync.rs:749-752` now requires `identity == Some("sifr.parallel.WorkerRuntimeError")`, but three pre-existing lowering fallbacks synthesize this type with `identity: None` whenever the user did not import it by name (`parallel_calls.rs:273-284`, `task_calls.rs:211-218`, `task_join_set_calls.rs:466-477` — the common `task.spawn_cpu` pattern). Pre-commit those classified as `RuntimeFault`; post-commit they classify as `OrdinaryError`, so Python `__exit__`/`__aexit__` receives the wrong exit cause and the evidence label degrades from `runtime-fault:…` to `ordinary-error:…`. Suppression refusal is unaffected (both are Sifr causes). Independently confirmed by two audits and by my own read of the diff; the new shadow test covers only the identity-`Some` shape. A related residual: a user class named `CancellationError`/`TimeoutError` declared in the entry module still carries `identity: None` and is misclassified as cancellation/timeout (the added test covers only the imported-shadow case).
**Remediation:** either preregister the stamped identity in the fallback constructors or match `WorkerRuntimeError` on `identity: None` too; extend the shadow test to the fallback and entry-module shapes.

**NM-3 — Class-level python decorators other than call-form `@python.opaque(...)` are silently ignored.**
`collect_python_opaque_declaration` (`python_interop.rs:460-483`) skips any non-`Call` decorator and any call not spelled exactly `python.opaque`; no other class-decorator validation exists. **Reproduced by me:** `@python(json.JSONDecoder)` on a fielded class passes `sifr check` silently and produces a plain structural class — the user believes the class is Python-bound. Same silent-acceptance class as NB-1, on the class surface.
**Remediation:** reject unknown/misplaced python decorators on classes with a stable PYCALL shape diagnostic; add negatives.

**NM-4 — The closure record itself is not closure-grade (pass-1 M8c unremediated, plus a false completeness claim).**
Evidence in Part 1 under M8: non-compliant archive status header, M17 `[x]` vs Wave 4 `[ ]`, no PR #3000 link anywhere, no explicit at-merge bookkeeping plan, and the new "Every actionable finding has been remediated with focused regression coverage" sentence contradicted by AM-1/AM-2/AM-6/AM-8/AM-10 below. Roadmap and phases-index PY-2 wording ("whole-phase review pending") was untouched and will freeze stale at merge exactly as pass-1 warned.
**Remediation:** record the at-merge finalization steps explicitly (or perform the pre-merge-safe parts now: link PR #3000 as the in-flight closure PR, reconcile M17/Wave-4 state, correct the completeness sentence), and flip status/roadmap/index in the merge unit.
