## Review — Item 1 (canonical receiver metadata and inference)

Scope reviewed: uncommitted working tree against `HEAD` (`cad0e8aaf`, the merge-base with `origin/main`; the `origin/main` delta contains unrelated distribution/governance work and is excluded). Supplied validation evidence taken as given; I ran no commands that build or test.

### What is solidly in place

- `ReceiverConvention` is a distinct three-mode enum on `FunctionType.receiver`, `HirFunction.receiver`, and `HirExpr::MethodCall.receiver_convention` (`crates/sifr_type_system/src/types/definitions.rs:302`, `crates/sifr_ir/src/hir_nodes.rs:149,682`), with `satisfies_protocol` variance matching the plan.
- `FunctionType.params` excludes `self` everywhere: every method-signature site skips index 0 (`class_type_collection.rs:363,417,747`, `class_body_lowering.rs:115,251,447`), and no `self_offset`/conditional-skip remains anywhere in the tree.
- Source compatibility for `own self` holds: `declared_receiver_convention` maps on `is_mutable()` only (`parameter_conventions.rs:6-19`), and `Owned` is applied only when declaration-first interop consumes the receiver (`class_body_lowering.rs:525-542`), asserted by `receiver_codegen_tests.rs:102` (`fn close(&self)`).
- Every production `HirExpr::MethodCall` construction site sets `Some(convention)` (14 sites; no `receiver_convention: None` outside tests), so no synthesized call is left unresolved.
- Speculative method borrow effects are gone: `record_flow_effect(Borrow{mutable:true})` removed from `mutating_methods.rs:71-77`, and `flow_graph/effects.rs:300-309` now derives the mutation effect from `receiver_convention == MutableBorrow`, with a negative test at `flow_graph/tests.rs:97`.
- `BindingId` retained facts survive frame pops and are patched post-inference (`scope.rs:388-408`, `method_receiver_analysis.rs:181-183`), with focused tests at `scope.rs:687,708`.
- Ephemeral classification is applied at all iteration/comprehension/match-capture sites and does not leak behavior: `is_inferred_local_binding` still gates on `BindingKind::Local` (`scope.rs:103`), and every mutability consumer gates on `is_parameter_binding()`, so `self` becoming `Receiver`/`Immutable` changes nothing today.
- All hand-maintained files are under 900 lines (max touched: `recursive_exprs.rs` 884). Five real splits landed (`while_loop.rs`, `method_calls.rs`/`literals.rs`, `protocol_bridge_emitter.rs`, `class_type_helpers.rs`, `hir_snapshot_expr_projection.rs`), and `class_method_receiver_analysis.rs` lost the codegen-owned inference as required.

### Material findings

**1. `method_call_needs_field_clone_suppression` was narrowed for owned-local roots — a new silent-clone path with no coverage. (High)**
`field_and_stdlib_rewrites.rs:41-63` deleted the old unconditional `return true` for class-typed field receivers and replaced it with a convention gate plus a root test that only accepts `self`, `borrowed_params`, or `mut_borrowed_params`. For `local.helper.bump()` — an owned local root with a class-typed field receiver — the old code suppressed the field clone; the new code falls through to the recursive-field check and returns `false`. Item 1 explicitly disclaims changing receiver-place behavior ("existing codegen behavior may continue to use the ambient field-clone counter until Item 2"), yet this silently regresses one shape in the wrong direction. The plan's owned-local field-receiver pass fixture is an Item 2 deliverable, and `expr_render_helpers/tests.rs:54,105` only cover `mut_borrowed_params` and `self` roots, so nothing in-tree proves this shape.

**2. `MethodCallSource.arg_ranges` is not aligned with `args` for class/protocol calls using keywords or defaults. (High)**
`method_calls.rs:309-313` stores `method_arg_ranges` derived from `resolved_method_arg_ranges` (`method_call_args.rs:53-58`), which is positional-AST-only apart from a few builtin `List`/`Dict`/`Str` keyword special cases. Class and protocol arguments, however, come from `lower_signature_call_args` (`method_call_arguments.rs:26-38`), which fills keyword arguments and defaults. So `self.helper.absorb(source=self.stock)` yields `args.len() == 1` with `arg_ranges.len() == 0`, and `h.configure(1)` on a two-parameter method with a default yields `2` vs `1`. The invariant check asserts only `source.is_some()` (`method_receiver_analysis.rs:253-257`); alignment is never asserted. Item 2's argument-footprint pass will zip these and silently drop the unranged argument — losing exactly the overlap diagnostic this issue exists to add. The task's "source calls require aligned ranges" criterion is not met.

**3. The canonical non-class receiver registry is materially narrower than the `MUTATING_METHODS` table it replaced. (High)**
`receiver_convention_for_non_class_method` (`mutating_methods.rs:11-19`) delegates to `is_collection_mutating_method` (`:92-125`), which classifies only `List`, `Dict`, `Set`, and `PythonBuffer("write")`. The deleted table (`queries_impl.rs`, old lines 6-27) also carried `write`, `push_str`, `anext`, `aclose`, `setdefault`, `popleft`, `appendleft` type-agnostically, and `collect_mutated_vars` (`queries_impl.rs:452-462`) is now driven *solely* by `receiver_convention`. Plan §2.1 requires "builtin list/dict/set/buffer/**iterator/handle** methods resolve from one canonical registry"; iterator and handle families are absent. Because the late Rust IR mutability pass only demotes (`ir_optimize/mutability_and_clone_rewrites.rs`), any receiver family that should be `MutableBorrow` but resolves to `SharedBorrow` loses `let mut` and fails in rustc rather than in Sifr. Note `stdlib/sifr/io.sifr:141` declares `def write(self, ...)` with no field mutation, so `FileHandle.write` resolves `SharedBorrow` while `close` (`:120`) resolves `MutableBorrow` — the mutability of an `open()` local now depends on which methods happen to be called.

**4. Protocol conformance was tightened in Item 1 while its diagnostic lands in Item 2. (Medium)**
`type_rendering.rs:679-685` now requires `cft.receiver.zip(pft.receiver)` and `satisfies_protocol`. Because module functions lower *after* the fixed point and `persist_method_receiver` rewrites `ctx.class_types`, a class method inferred `MutableBorrow` that implements a `SharedBorrow` protocol method now fails structural conformance with an opaque type mismatch instead of `SIFR-PROTO-0005`. Worse, `HirClass.implements_protocols` was computed earlier from *declared* conventions, so the class still claims the protocol and `protocol_bridge_emitter.rs:20-27` emits an `&self` bridge delegating to a `&mut self` method — non-compiling Rust. The two halves disagree for the whole Item 1/Item 2 window. Also, `zip` silently fails conformance whenever either side is `None` (static/class-method signatures get `receiver: None` at `class_type_collection.rs:747`).

**5. The invariant check is not the post-pass the plan specifies, and has a reachable assert on a valid-shaped call. (Medium)**
Plan §1 requires "a focused lowering post-pass before `LoweringResult` construction" plus "focused tests … with compiler-authored malformed HIR". What exists are asserts embedded in the annotation walk (`method_receiver_analysis.rs:243-257`), invoked only over class methods/operator impls and module functions (`module_body_lowering.rs:20,39-41`); there is no pre-`LoweringResult` pass and no malformed-HIR test. Separately, `signature.receiver.unwrap_or_else(|| assert!(source.is_none(), …))` panics for any resolved instance-syntax call whose signature has `receiver: None` — `instance.static_helper()` type-resolves through `resolve_class_method_type` with no `method_kind` filter, so the signature found is the `receiver: None` static entry. I could not find a fixture exercising instance-syntax static calls (all of `staticmethod_basic.sifr`, `demos/inheritance/main.sifr` call via the class), so this is plausible rather than confirmed — but if reachable it converts a shape into `SIFR-INTERNAL-0001`.

**6. `rust_receiver_param` panics in codegen instead of relying on a proven lowering invariant. (Low–Medium)**
`class_method_emitter.rs:12-15` uses `panic!` for a missing convention. The plan places that invariant in lowering and says codegen must not default it; a bare `panic!` in the emitter is the third-best option and, given finding 5, is not backed by a proven pre-codegen check.

**7. Receiver-metadata snapshot coverage is thin. (Medium)**
`verification/areas/core_language/data/hir_lowering_snapshot_matrix.json` contains **zero** `MethodCall` cases, so the new `receiver_convention`/`source` projection (`hir_snapshot_expr_projection.rs:131-152`) is never exercised there. The only snapshot evidence is one `SharedBorrow` builtin call in `name_resolution_snapshot_matrix.json:156`. Plan step 7 asks for "HIR snapshot, inheritance, protocol, opaque/builtin" tests; there is no `Owned`/declaration-first receiver test anywhere, and no `sifr_ir` receiver test at all.

**8. Residual string-keyed receiver logic contradicts the new binding model. (Low–Medium)**
`class_semantics.rs:9-27` seeds mutability from `object == "self"`, and `helpers_impl.rs:641-650` / `field_and_stdlib_rewrites.rs:49` still key on the literal `"self"`. The plan states root eligibility must test binding kind plus final convention, "never the literal name `self`", and `BindingKind::Receiver` is currently consulted in exactly one place (`method_receiver_analysis.rs:352`).

**9. `binding_id` is not universal. (Low)**
`module_constants_lowering.rs:219` emits `HirExpr::Name { binding_id: None }`, so module-constant roots carry no id and Item 2's `Place` root equality cannot distinguish them. Plan §3 says "Every lowered `HirExpr::Name` carries the resolved id."

**10. Named decomposition not landed for a file this change grows. (Low)**
`intrinsic_method_emitters/recursive_exprs.rs` went 882 → 884 (+4/−2) without the plan-mandated extraction of recursive registry method-call lowering; the plan requires each named split to land "before or in the first PR that otherwise grows that file". The same named splits for `field_and_stdlib_rewrites.rs`, `queries_impl.rs`, `stmt_expr_wrappers_and_compare.rs`, and `statements/statement_dispatch.rs` were also skipped, though those files shrank or were unchanged in size.

### Assessment

The metadata plumbing, `self`-out-of-params normalization, `own self` source compatibility, speculative-effect removal, and file-size compliance all hold up. But findings 1–3 are material: one is a new silent-clone path in the exact defect class this issue exists to close, one breaks the "aligned ranges" precondition Item 2 depends on, and one replaces a broad mutating-method table with a registry covering four type families while making local-mutability inference depend solely on it. Finding 4 leaves protocol conformance and protocol bridge emission mutually inconsistent for the duration of the item, and finding 5 means the mandated invariant post-pass and its malformed-HIR test do not exist.
