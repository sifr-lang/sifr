## Review — `hardening_3` (Rust interop evidence provenance)

Scope checked: the working diff (70 modified + 1 new check module + 1 new Rust test file), `_provenance_checks.py`, both matrix checkers, all 34 schema-v2 manifests/READMEs (script-verified: 47 passing sides, all with `validation`; all 11 non-passing sides unbound; every README repeats evidence id + test name + file + suite + profile exactly), and the four profiles. Mechanical parts are strong: schema/field-set enforcement, package/file containment, exactly-once uncommented test definition (comment/raw-string/nested-block stripping is genuinely careful), `--ignored`↔command coupling, weakest-blocking-profile derivation, and one-test-per-side reservation all work, and the 5 ignored generated-build bindings line up with `sifr_driver_generated_builds` at `merge`. Nine of the plan's enumerated mutation cases are present and real (temporary trees only, no checked-in edits).

What is not compliant is the *appropriateness* half of the requirement: several bindings certify a row with evidence weaker than, or off-subject from, the row's declared `execution_kind`, and the validator has no rule that could catch it.

### 1. HIGH — `runtime-observed` row certified by a compiler-diagnostic lowering test
`verification/areas/rust_interop/fixtures/async_runtime_core/fixture.json:14-17` binds negative `stdlib_async_hidden_blocking_rejected` to `crates/sifr_lowering/src/lower/rust_interop_tests.rs:333`. The row is `execution_kind: runtime-observed` (tier 2), whose frozen meaning is "executed lifecycle/runtime behavior"; the bound test lowers source and asserts a diagnostic — that is tier-0 `compiler-diagnostic` strength, not even `contract-only`. It is also the same code path as `rust_interop_rejects_blocking_classification_on_async_function:316` (bound to `blocking_diagnostics` negative), so the distinctness rule is satisfied lexically while the behavior is shared. The assertion is additionally weak: `any(code == RUST_ASYNC_CONTRACT)` passes for any async-contract rejection, not specifically hidden blocking.
Fix: add a real runtime-observed negative in `crates/sifr_runtime/src/interop.rs` (async resource observing rejected/hidden-blocking misuse), bind that, and assert the specific message/kind — or, if no runtime negative exists yet, demote the row's claim rather than the evidence.

### 2. HIGH — tier-1 `cargo-probe` row certified by metadata-only evidence and by another family's subject
`fixtures/local_bridge_blake3/fixture.json:27-29` binds positive `local_bridge_hash_bytes` to `crates/sifr_driver/src/build/rust_interop_tests.rs:167`, which builds no crate and runs no probe — it asserts an injected `use __sifr_bridge_package_sifr_app::bridges as bridge;` string in `support_modules`. That is weaker than contract-only for a row the issue explicitly forbids weakening ("Do not weaken tier 1 to permit contract-only evidence"). The negative (`fixture.json:14-16` → `rust_interop_tests.rs:513`) does run a real rustc probe, but its subject is a **direct backend** crate (`native.missing` via `backend_with_manifest`), not a missing **package-local bridge** export, i.e. it certifies `missing_local_bridge_export` with `direct_crate_*` behavior.
Fix: add `package_rust_interop_local_bridge_probe_accepts_bridge_export` / `..._rejects_missing_bridge_export` that materialize a package bridge root and run the probe (mirroring `package_rust_interop_direct_probe_accepts_bridge_signature:99`, or the ignored `package_rust_interop_build_tests.rs` pattern) and bind those.

### 3. MEDIUM-HIGH — `callback_subscription_core` bound to Python-interop and contract-only tests, and that forces a new blocking suite
Row is tier-2 `runtime-observed`, capability "stdlib-owned signal callback subscriptions and shutdown". Positive (`fixtures/callback_subscription_core/fixture.json:27-29`) binds `crates/sifr_runtime/src/python/callbacks/tests.rs:428`, a pyo3 Python callback-owner test asserting `SifrCallbackClosedError`; negative (`:14-16`) binds `crates/sifr_driver/src/build/rust_interop_callback_contract_tests.rs:126`, a contract-only driver check — again weaker than the row's declared strength. Because `pub mod python` is `#[cfg(feature = "python")]` (`crates/sifr_runtime/src/lib.rs:15`), this binding is the sole reason `sifr_runtime_python` was added as a **blocking smoke suite to all four profiles** (`verification/profiles/create-pr.json:79` and peers), putting a pyo3/Python-toolchain build into the fast PR lane for evidence that is off-subject.
Fix: bind both sides to Rust-interop callback lifecycle tests under `crates/sifr_runtime/src/interop.rs` (adding them if absent) and drop the `sifr_runtime_python` suite unless it is justified independently.

### 4. MEDIUM — validator accepts a feature-gated test bound to a suite that cannot compile it (demonstrated)
`_provenance_checks.py:188-228` checks only package containment; `_validate_test_definition` ignores `#[cfg(...)]`. I temporarily set `async_runtime_core` positive `suite_id` to `sifr_runtime` (default features) — `check_fixture_matrix.py` exited 0 even though `async_handle_close_and_cancel_join_are_deterministic` is `#[cfg(feature = "net")]` (`crates/sifr_runtime/src/interop.rs:488`) and no default-feature suite runs it. (File restored; verified.) This directly defeats "resolves to one exact Rust test executed by a blocking mandatory local profile."
Fix: collect `#[cfg(feature = "…")]` on the test and its enclosing `mod`/file, resolve the suite command's `--features`/`--no-default-features` through the package's feature closure, and reject unimplied gates; add a mutation case.

### 5. LOW-MEDIUM — suite `--skip` filters are ignored
`_weakest_executing_profile` (`_provenance_checks.py:339-358`) only inspects `--ignored`. `sifr_lowering` and `sifr_cli_full` run with `-- --skip test_e2e_pass`; a bound test whose name matched a skip filter would be certified but never executed. Latent today. Fix: reject bindings whose `test_name` contains any `--skip` argument of the selected command.

### 6. LOW-MEDIUM — two core rules have no mutation coverage
`run_self_test` covers the nine enumerated cases, but not the weakest-profile rule (`_provenance_checks.py:129-136`) nor package-ownership rejection (`:202-210`) nor `step != crate_tests` / bad field-set. Both untested rules are load-bearing for the merge-profile bindings. Fix: add cases (bind the `driver_ignored` suite while claiming `create-pr`; bind a `crates/sifr_lowering/...` path to the `sifr_driver` suite).

### 7. LOW — trap-prone precedence in duplicated selection logic
`_provenance_checks.py:181` and `:350` read `if selected_mode not in modes if isinstance(modes, list) else True:` — a conditional expression, correct today but easily misread and edited into a silent accept-all. The same blocking/mode logic is also duplicated between `_validate_suite_selection` and `_weakest_executing_profile`. Fix: extract one `_suite_enabled(profile, suite) -> bool` helper with an explicit `if not isinstance(modes, list): return False`.

**Root cause behind 1-3:** the schema mandates exactness but nothing ties `execution_kind` to the *kind* of bound test, so the migration could satisfy the checker with the nearest existing test. The mechanizable fix inside this milestone's mandate is an `execution_kind → allowed evidence source` policy in `_provenance_checks.py` (runtime-observed ⇒ `crates/sifr_runtime/**`; cargo-probe ⇒ a test that materializes a crate/probe, e.g. restricted to the generated-build suites or an explicit probe marker; compiler-diagnostic ⇒ lowering/driver diagnostic files), plus mutation tests for each rejection.

Non-issues confirmed: README prose is no longer validator input (only existence is checked, `check_fixture_matrix.py:196`); non-passing evidence is unbound and rejected if bound; `bridge_version_mismatch`, `direct_crate_*`, `opaque_handle_tokenizer`, `async_ecosystem_matrix`, `panic_*`, `zero_copy_*`, `close_after_use`, `opaque_resource_core` bindings are behavior-appropriate (the probe tests do write real crates and invoke rustc). File sizes pass, though `check_fixture_matrix.py` is now 857/900 lines — worth splitting before `hardening_4` adds to it. `rust_interop_checks` measures ~0.7s against its 5000 ms blocking budget, so the added parsing is safe.

Actionable findings: 7. CHANGES REQUIRED.
