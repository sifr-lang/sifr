## Actionable findings — all NON-BLOCKING

**F1 — DLPack failed-transfer cleanup can double-free unless the fresh consumer capsule is neutralized first.**
`internal_docs/python_interop_protocol_architecture.md`, *DLPack*, lines 529–536. When an owned `DlpackTensor` is passed to a Python consumer, Sifr creates a fresh `dltensor` capsule whose destructor (per spec) must invoke the deleter if unconsumed. The text says: "If it fails before consumption, generated cleanup invokes a non-null producer deleter exactly once" — but that capsule object was already handed into the Python call and remains alive until GC. If generated cleanup invokes the deleter directly *without first renaming its own consumer capsule to the used sentinel*, the capsule destructor later fires on the still-`dltensor`-named capsule and invokes the deleter a second time — a double free. The acquisition-side rule (lines 527–530) states the rename-before-assume principle, but the failure-before-consumption path never restates it, and a conforming-looking implementation can follow the sentence literally into memory corruption. **Correction:** add one sentence at line ~534: "On failure before consumption, generated cleanup first renames its unconsumed consumer capsule to the used sentinel, disabling the capsule destructor, then invokes the deleter exactly once." Mirror in plan M12 (lines 546–549). (Arrow needs no analogous clause because the C Data Interface requires release callbacks to null themselves; DLPack deleters have no such convention — the rename is the only guard.)

**F2 — `__enter__`/`__aenter__` returning a distinct opaque class with a non-`drop` cleanup policy silently abandons semantic cleanup.**
`python_interop_protocol_architecture.md`, *Synchronous Context Managers*, lines 244–249. "If Python returns distinct opaque identity, the hidden context owner retains that object and releases it after exit" — ordinary reference release. Nothing prevents an author from declaring `__enter__(self) -> Result[Session, PythonError]` where `Session` is `@python.opaque(cleanup=close)`. The hidden owner then discharges a must-close value by plain drop — exactly the abandonment the *Cleanup Policies* section (line 148: "Ownership analysis rejects paths that can abandon a value requiring semantic close") forbids, but through generated machinery the user-facing must-use analysis never sees. One implementer rejects the declaration; another silently drops. **Correction:** add a declaration-check rule (SIFR-PYCTX-*): an opaque entered value must be the manager class itself (the `__enter__ -> self` shape) or a class with `cleanup=drop`; a class requiring semantic close cannot be a context-scoped-borrow entered value. Add a negative fixture to plan M5/M8.

**F3 — Protocol acquisition for non-`Self` buffer/Arrow/DLPack targets is unspecified.**
`python_interop_protocol_architecture.md`, lines 383–386 (buffer), 410–413 (Arrow), 471–487 (DLPack). The global target grammar (declaration doc, lines 148–152) permits import-root, `bridge`, and `Self` roots for every decorator, but every `@python.buffer`/`@python.arrow`/`@python.dlpack` example uses `Self`, where the receiver *is* the producer and the protocol dunder is invoked directly. Only `@python.dlpack.stream` demonstrates the callable-target shape (target invoked with declared args, result normalized). For `@python.arrow(bridge.frames.make_stream)` it is undefined whether the wrapper calls the target with declared parameters and then acquires from the result, or whether non-`Self` targets are rejected. Two implementers diverge at compile time on declarations no example exercises. **Correction:** state the acquisition pipeline explicitly per decorator kind — e.g., "a `Self` target acquires from the receiver; any other target is evaluated as a call with the declared non-protocol parameters and acquisition applies to its result" — or restrict `@python.buffer/.arrow/.dlpack` targets to `Self` and route everything else through bridges.

**F4 — `AsyncCallable` is a net-new surface type and `crates/sifr_type_system` is missing from the plan's Scope.**
`python_interop_declaration_architecture.md` line 236 (conversion table) and `python_interop_protocol_architecture.md` line 323 use `AsyncCallable` normatively; plan M9 (line ~439) says "Implement asyncio-dispatched `AsyncCallable`". Ground truth: only `Type::Callable` exists (`sifr_type_system/src/types/definitions.rs:119`); `AsyncCallable` appears nowhere in code, and the closest type (`Type::AsyncFunction`) is explicitly not assignable to `Callable`. Meanwhile the plan's Scope (`plans/issues/active/ad-hoc-declaration-first-python-interop.md` lines 85–106) omits `crates/sifr_type_system` entirely, even though unions, `Callable`, `ParamOwnership`, and the new compiler-known types (`python.Buffer[T]`, `python.DlpackTensor[T]`, `python.ExitCause`, …) live or will live there. **Correction:** add `crates/sifr_type_system/` to Scope, and make the M9 task explicit that `AsyncCallable[[...], R]` is a net-new annotation production parallel to `Callable`, so an implementer doesn't hunt for an existing type.

**F5 — The Arrow "requested schema" clause references an inexpressible feature.**
`python_interop_protocol_architecture.md`, lines 428–430: "A requested schema is omitted unless that certification also proves the request is representation-preserving," and the artifact records a "requested schema policy" (line 436). No decorator argument, parameter convention, or grammar production anywhere lets an author *request* a schema, so the "unless" branch is unreachable as specified and the artifact field has exactly one possible value. **Correction:** either state that the shipped end state always calls `__arrow_c_array__`/`__arrow_c_stream__` with `requested_schema` omitted and the artifact field is fixed to `omitted`, or define the decorator surface that expresses a request. Do not leave a policy knob with no syntax.

**F6 — Call-scoped callback error observation is underspecified for foreign/parallel dispatch and for swallowed errors.**
`python_interop_protocol_architecture.md`, lines 323–336. The retained-callback path has a complete observation contract (first failure recorded on the owner; shutdown diagnostics report unobserved failures). The call-scoped path says only that the handler error "enters the enclosing declaration's error channel when the Python target propagates it." Two gaps: (a) `lifetime=call` is not restricted to `dispatch=current`, so a call-scoped foreign/parallel callback can produce multiple concurrent handler failures during one call — no selection rule is stated; (b) if the Python target catches and swallows `SifrCallbackError`, the handler error vanishes and the declaration returns `Ok` with no evidence, which sits uneasily beside the retained path's "reported if no operation observes it" guarantee. **Correction:** state the first-failure rule for call-scoped callbacks across all dispatch modes, and state explicitly that a Python target catching `SifrCallbackError` counts as observation (or is recorded as cleanup-style evidence) — pick one and say it.

**F7 — `sifr python certify` ownership is split between M11 and M14.**
Plan, M11 (lines 507–509) delivers "the package-authored `sifr python certify arrow` fixture/artifact workflow and read-only certification recheck"; M14 (lines 601–602) says "Add `sifr python certify` authoring and `certify --check`" as if new. M11 *must* contain the Arrow workflow (since `@python.arrow` acceptance gates on recorded certification), so M14's "Add" is really "generalize/extend," and the first `sifr python` CLI subcommand actually lands at M11, before M13 nominally introduces the family. **Correction:** reword M14 to "extend the certify surface landed in M11 (Arrow) to the general protocol-evidence and drift contract," and note in M11 that it bootstraps the `sifr python` subcommand group.

**F8 — Staged-activation boundaries for grammar locked at M0 are unannotated.**
Plan, *Delivery Rule* (lines 108–114) and M3 (lines 208–249). The complete grammar locks at M0, but activation is staged: `bridge.*` roots cannot execute before M6, `cleanup=close|context` semantics before M4/M5, `@python.coroutine` before M7. The plan never states what a not-yet-activated-but-grammar-valid declaration does on intermediate mainline (reject with which diagnostic?). This does not create a reduced *published* language, but each intermediate state should be pinned so "one production path per activated behavior" is checkable per merge. **Correction:** add one line per affected milestone naming the forms it activates and the diagnostic rejecting them beforehand.
