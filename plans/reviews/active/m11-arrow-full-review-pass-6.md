## New findings

**Minor**

- **F1 — Reclassifying `__pow__` as an operator dunder drops inherent emission for non-affine `__pow__`; explicit `a.__pow__(x)` calls that built on main are now check-clean → E0599 (introduced by 69d316412; loud, exotic-only, zero in-tree usage).** Adding `__pow__` to `OPERATOR_DUNDERS` routes it into `operator_impls` at `class_body_lowering.rs:625`, and `emit_operator_impls` (`operator_protocol_emitters.rs:53-77`) has no `__pow__` arm — the `_ => {}` catch-all emits nothing (no Rust `**` trait exists). Reproduced live: `class Acc: def __pow__(self, other: int)` + `a.__pow__(3)` checks clean and fails at build with E0599; on main `__pow__` was a regular method and would have emitted an inherent fn (verified: main's `OPERATOR_DUNDERS` lacks `__pow__`; HEAD emits the analogous regular dunder `__getitem__` verbatim and it runs). Severity calculus: the *only* newly-broken shape is the explicit dunder-name call — `a ** b` on classes never dispatched to `__pow__` in codegen and fails E0599 identically on main and HEAD (reproduced both); explicit calls of every *other* operator dunder (`a.__add__(b)`) were already E0599-broken on main (reproduced); seven pre-existing `OPERATOR_DUNDERS` members (`__floordiv__`, `__ne__`, `__le__`, `__gt__`, `__ge__`, `__pos__`, `__contains__`) already have this exact declared-but-never-emitted profile on main, so HEAD's `__pow__` now matches main's `__contains__` exactly; there is no silent path (declared-but-unused emits nothing harmlessly; every call form — explicit, `**`, protocol — fails loudly at rustc); affine operands are unreachable (PYZC-0001 at declaration, the point of M-E); and a repo-wide sweep found **zero** in-tree `__pow__` usage in demos, stdlib, docs, verification, or any `.sifr` file. This is materially below the pass-3b B-1 blocker bar (there, a previously-correct check-time diagnostic was lost on a shape users naturally write) and matches the profile pass 5 classified minor (imported-dunder class-style calls: check-clean → loud rustc, no affine involvement). The fix pass 5 prescribed for M-E was literally this list addition. **Recommended follow-up** (next time the operator surface is touched): give `__pow__` the M-F treatment instead — remove it from `OPERATOR_DUNDERS` and add `|| method_name == "__pow__"` to the special case at `parameter_conventions.rs:90` — or add a `__pow__` emitter arm plus `**` dispatch; and add an emit-path test for one non-affine operator dunder, which is exactly the coverage hole that made F1 invisible to the green suite.
