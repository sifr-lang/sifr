## Findings

### MINOR-1 — The "isolated" didOpen benchmark builds its temp package but measures a different, package-less directory, contradicting the ledger's isolation claim

**Files:** `verification/areas/performance/lsp_query_bench.py:334-335` versus `:240-269` and `:285-322`; `plans/issues/active/ad-hoc-declaration-first-python-interop.md:2307-2309`.
**Evidence:** For `lsp-query-018-did-open-diagnostics` (`workspace_mode: "isolated"`), `main()` enters `benchmark_source`, which constructs the full temporary locked package and writes the source into it — but `run_scenario`'s `lsp.did_open_diagnostics` branch ignores `benchmark_path` entirely and calls `run_did_open_diagnostics(source, …)`, which creates its **own** bare `sifr-lsp-did-open-bench-` temp directory with no `sifr.toml`, `Cargo.toml`, or lockfile and opens documents there. Those documents have no package root (`package_root_for` finds nothing above `/tmp`), so this case measures the package-less document-sync path — identical to pre-fix behavior (no measurement regression, and the recorded numbers are unaffected) — while the constructed temp package is dead setup. The ledger sentence "isolated cases execute in a minimal temporary locked Sifr/Cargo package" is therefore inaccurate for 1 of the 14 isolated cases.
**Rationale:** Milestone-closure accuracy — this series corrected plan-ledger wording at pass 3 for exactly this class of overclaim, and the dead construction misleads future maintainers into believing the didOpen case exercises the temp-package path when it can never exercise environment resolution at all.
**Remediation:** Either skip temp-package construction for `lsp.did_open_diagnostics` (make `benchmark_source` scenario-aware) and qualify the ledger sentence ("warm/cold isolated cases execute in a minimal temporary locked package; the didOpen sync case runs in a bare temporary directory as before"), or deliberately route the didOpen documents into the temp package's `src/` — the latter changes what the case measures and would require baseline justification, so the first option is recommended.

### MINOR-2 — The durable performance reference does not record the new required `workspace_mode` semantics

**File:** `internal_docs/performance_budgets.md:76-101` (LSP case mechanics section).
**Evidence:** The doc is the durable policy reference for the benchmark corpus and documents LSP-case mechanics at exactly this granularity — which cases run against `query_projects/lsp_workspace/`, how warm cases use `inner_repetitions`, how RSS is measured. It contains no mention of the now-**required** `workspace_mode` manifest field, its two-way validation, or the fact that the 14 isolated cases execute in a synthetic temporary locked package rather than in-repository (the very change that explains the step-change in this milestone's recorded RSS from 103.5 to 71.5 MiB). A reader interpreting trend history or authoring a new LSP case from this doc would find an undocumented mandatory field. `lsp_query_budget_ids.md` is similarly silent but is an id-namespace registry, so only the budgets doc needs the update.
**Rationale:** Established convention — this doc was updated in-unit when the LSP cases were introduced (the `lsp-query-001` bullet), and AGENTS.md requires internal reference docs to track shipped behavior; leaving the execution-context redefinition of 14/18 LSP cases recorded only in the issue ledger leaves the durable reference materially incomplete.
**Remediation:** Add two or three sentences to the LSP section: every `lsp-query` case must declare `workspace_mode` (`isolated`/`package`), validation cross-checks the mode against sibling-manifest presence, isolated cases execute in a deterministic minimal temporary locked Sifr/Cargo package to avoid upward attachment to the repository workspace, and package cases run the checked-in `lsp_workspace` fixture in place.
