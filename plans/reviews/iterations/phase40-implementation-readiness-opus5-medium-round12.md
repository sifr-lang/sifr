## Optional polish (non-blocking)

1. **Cross-doc drift — open since round 3; both issue files are modified in the working tree.** `plans/issues/active/rust-interop-verification-matrix-hardening.md:12-13` and `plans/issues/active/rust-interop-runtime-ecosystem-certification.md:137,158-159` still name `milestone_40_1` / "the `milestone_40_4` activation gate" as the stable-candidate consumer, while `40:56-61` requires both artifacts *before* `milestone_40_0` and `40:370-371` registers the suite there. `plans/phases/index.md:50` still shows Phase 40 status `unspecified` vs `40:3` `implementation-ready`.
2. **`40:512-515` folds a non-queryable property into an artifact-resolution check.** The Actions API exposes an artifact's name, size, digest, and expiry, but not the `overwrite` setting used at upload; "resolves to an unexpired, **overwrite-disabled** artifact" is only checkable as a workflow-configuration assertion. Split it: a repository check asserts `overwrite: false` + immutable names in `release-qualification.yml` (`40:471-473`), and the plan-time check asserts unexpired + digest + source identity.
3. **What the index's SHA-256 values hash is unstated** (`40:475-478`). Artifact transport re-zips on download, so zip bytes are not stable; state that the recorded digests are of the contained release files — the same file-level digests the plan already binds at `40:231-232` — otherwise `40:512-515` is unimplementable as written.
4. **Retention-window prerequisites for the seven-day floor** (`40:817-820`). (a) `retention-days: 30` is silently clamped to the repository/org maximum; add confirming that limit to the M40.0 environment definitions alongside the GA version and OS/ABI floors (`40:391-392`). (b) Artifacts expire per upload time, so name the floor's reference point as the **earliest** recorded artifact expiry. (c) No surface mechanically enforces the floor — `prepare` only requires "unexpired" (`40:879`) and surfaces expiry in its summary (`40:882-884`); a `prepare`-time floor check plus a negative ("a candidate with fewer than seven days remaining fails prepare") would make `40:817-820` falsifiable rather than advisory. Behavior is already fail-closed at publish time, hence non-blocking.
5. **VSIX authority is inferable but not stated.** `40:467-470` has the qualification run package the VSIX, `40:512-515` requires it in the index, and `40:827`/`40:835` require M40.5 to consume "the recorded VSIX without rebuilding" — yet M40.4 separately runs local `packaging` (`40:794-796`) and "Produce[s] exactly one VSIX" (`40:804-805`). Since `vsce` output is not byte-reproducible across runs, say explicitly that the plan-bound VSIX digest is the qualification run's uploaded artifact and that local packaging is validation-only. Same for the missing counterpart of `40:806-808`: M40.4 should state "dispatch `release-qualification.yml` at the exact final source commit" rather than leaving it implied by `40:809` "candidate artifacts … final".
6. **`40:195-203` still interrupts the "Schema ownership" bullet list with two prose paragraphs, orphaning the `40:204-205` installer bullet** (carried from R11). Also: `qualification-artifact-index.json` is the one machine-readable release artifact absent from that section and from M40.0's schema check-in list (`40:349-355`); giving it a `schema_version: 1` contract and validator would match how every other contract is treated.
7. **Cosmetic, carried since round 1.** `distribution_release --suite full` (`40:999`) implies a scope distinction the manifest does not make — `representative` and `full` bind the identical `distribution-cases` case (verified in `verification/areas/distribution_release/manifest.json`).
8. **Tension between the new CI qualification matrix and `40:1053` ("No CI-only semantic validation is allowed") / `40:1026-1027`.** Four-target host install/smoke is inherently runner-provided and cannot be reproduced on one workstation; the local demo at `40:527-530` is host-local only. State the hardware exception explicitly (multi-target artifact qualification is runner-provided evidence and never substitutes for a local semantic gate) so the Quality Contract is not read as prohibiting `40:466-467`.
